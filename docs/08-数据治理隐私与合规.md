## 1. 这份文档要解决什么

**问题：** 万径要做「导入用户 ChatGPT / Claude / DeepSeek 历史对话来构建个人画像」，这是整个产品最有价值、也最容易出事的一步。如果治理规则写得含糊，工程上就一定会沿着「多拿数据 → 画像更准」的方向滑过去。本文的任务是把这条滑梯拆掉，换成一条虽然更慢但每一步都可解释、可撤回的路径。

**一句话结论：** 万径的数据治理不是「合规部门贴在产品后面的免责声明」，而是产品能力的一部分——**用户之所以愿意交出对话记录，是因为他能随时看到系统拿这些记录得出了什么结论、依据是哪一句话、以及一键删掉之后会发生什么**。可撤回不是成本，是可撤回本身构成了信任。

由此得到本文贯穿始终的四条治理原则 `[已确定]`：

1. **最小必要**：能用「用户自陈 + 少量证据」达成的结论，不得为了精度去拉全量对话。
2. **证据可溯**：任何一条画像结论必须能指回原始片段、时间戳与置信度；指不回去的结论不得进入画像。
3. **用户主导**：授权默认关闭、按场景逐项开启；查看、纠正、导出、删除是产品功能，不是客服流程。
4. **默认不共享**：考生数据默认不出考生端；向高校侧输出必须是考生逐次主动授权的行为。

### 1.1 一处明确的取舍

**我们放弃了「用全量历史对话训练/微调模型以换取更高画像精度」这条路。** 原因有三：其一，全量对话里混杂他人信息（对话对象、群聊内容），我们无法可靠地取得第三方同意；其二，全量投喂会让「某条结论对应哪段原文」这件事在工程上不可回溯，直接违反原则 2；其三，模型的边际精度提升无法向用户解释，却要用户承担全部风险，收益与风险不对等。

代价是画像的冷启动更慢、单条结论的证据密度更低。我们接受这个代价，用「多轮探针 + 用户纠正」补，而不是用「更多原始数据」补。

## 2. 数据分类分级

分级的目的不是归档，而是决定**三件事**：能不能默认采集、能存多久、能出哪个边界。下表是本文的强制分类 `[已确定]`。

| 级别 | 数据类型 | 来源 | 默认采集 | 默认留存 | 可否出考生端 |
| --- | --- | --- | --- | --- | --- |
| L0 公开 | 招生章程、招生计划、选科要求、专业目录 | 考试院 / 高校官网公开发布 | 是 | 随年度版本 | 是（公开） |
| L1 受限 | 高校提供的非公开培养方案细节、宣讲素材 | 高校授权 | 否，需授权 | 合同期 + 约定 | 仅站内展示 |
| L2 一般个人 | 省份、年级、选科、自陈兴趣、探索记录 | 考生填写与行为 | 是（需同意） | 账号存续期 | 是（本人） |
| L3 敏感个人 | 第三方 AI 对话原文、家庭/健康/情绪相关表述、精确联系方式 | 考生主动导入 | **否**，单独同意 | 最短必要（见 §3） | 是（本人） |
| L3-M 未成年人 | 未满 18 周岁考生的全部 L2/L3 数据 | 同上 | 否，需监护人流程 | 同 L3 | 是（本人 + 监护人） |

三条硬规则 `[已确定]`：

- **L3 不得与 L2 合并成一张宽表。** 物理分表、独立密钥、独立留存策略。这样「删除对话」不会误伤画像条目，「删除画像」也能级联清理证据。
- **未成年人数据单独标识。** 未满 18 周岁在系统中必须有显式标记，未标记的账号按未成年人处理（宁可误判为未成年，不可误判为成年）。
- **L0 也必须标注来源与年度。** 公开数据不是「没有治理成本的数据」，它的风险是过期与张冠李戴，见 §10。

> **跨文档待核对：** 本节要求画像条目与证据片段**分表存储**（条目只存证据引用 ID，证据独立存储、独立密钥、独立留存策略）。03 §5.3 的 `evidence_refs` 与 07 的画像条目定义目前都按「引用」处理，方向一致；需在 07 的物理表设计中确认证据未被内嵌进条目，否则本条无法落地。

## 3. 数据全生命周期

```text
  采集                存储                 使用                共享                留存/删除
+--------+        +------------+       +------------+      +------------+      +------------+
| 明示   |        | L2/L3 分表 |       | 最小必要   |      | 考生逐次   |      | 到期自动   |
| 同意   | -----> | 独立密钥   | ----> | 场景限定   | ---> | 主动授权   | ---> | 降级/删除  |
| 可跳过 |        | 审计开启   |       | 全程留痕   |      | 字段白名单 |      | 级联清理   |
+--------+        +------------+       +------------+      +------------+      +------------+
     |                  |                    |                   |                   |
     v                  v                    v                   v                   v
  拒绝即不采集      不存原始全文         不用于录取决策      不出原始证据        撤回即生效
```

### 3.1 采集

- 每一项采集在界面上必须回答三个问题：**收什么、为什么、不给会怎样**。答不出来的字段不上线。
- 授权是逐场景的，不是逐文档的。用户同意「导入对话用于生成画像」，不等于同意「画像用于向高校展示」。
- 允许「先体验后授权」：不导入任何对话也可以使用自我探索与专业发现，只是画像证据更薄。这条是产品约束，不是运营话术 `[已确定]`。

### 3.2 存储

| 对象 | 加密 | 留存默认值 | 状态 |
| --- | --- | --- | --- |
| 第三方对话原文 | 应用层加密 + 独立密钥 | 30 天，用户可设「立即删除」 | `[设计中]` |
| 用户确认的证据片段 | 同上 | 随画像条目存活 | `[设计中]` |
| 画像条目 | 库级加密 | 账号存续期 | `[设计中]` |
| 审计日志（不含正文） | 追加写 + 哈希链 | 180 天 | `[假设]`，需法务确认下限 |
| 合成/脱敏测试数据 | 不适用 | 不设 | `[已确定]` |

**开发与测试环境一律使用合成数据，禁止把生产数据导出到个人设备或笔记本。** 这条没有例外，违反即视为安全事故 `[已确定]`。

### 3.3 使用

- 用途白名单：画像生成、自我探索引导、专业匹配解释、用户主动发起的分享。**白名单之外一律拒绝**，包括「内部数据分析」——后者必须走独立的、去标识化的数据集。
- 每一次画像读取记录一条访问日志：谁（服务身份）、读哪条、为什么（调用来源）、结果是否被使用。

### 3.4 共享

- 不出考生端是默认值。向高校侧的输出必须由考生在当次会话中主动开启，且以「摘要 + 解释」形态给出，**不给原始证据片段**（原文可能含家庭、情绪等与专业探索无关的内容）。
- 任何共享行为在考生侧可见、可撤回，撤回在下一个请求周期内生效。

### 3.5 留存与删除

- 删除是**级联**的：删除画像条目 → 删除其证据引用 → 无其他引用的证据片段进入待清除队列。
- **软删除与硬删除分两段**（对应 03 §5.5 的「回收站」要求）：用户删除后进入回收站，回收站保留 30 天，期间可恢复；到期执行硬删除；用户可勾选「立即彻底删除」跳过回收站。界面文案必须写成「删除后可在 30 天内恢复，到期彻底删除」，不得写成「删除后立即清除」。
- 硬删除有时限：用户发起彻底删除后 7 天内完成，备份轮转 30 天内清除。时限必须在界面上明写，不能写「尽快」。
- **撤回授权不等于删除数据**，两个动作必须在界面上分开呈现，否则用户会误以为撤回即删除。这是本设计里最容易造成信任崩塌的一处细节。

> **取舍：** 我们放弃了「删除后保留匿名化副本用于模型改进」这一常见做法。匿名化在对话文本上很难做到可验证的不可复原（对话里的自述细节具有强标识性），与其做一个无法证明的匿名化，不如直接不留。

## 4. 授权模型

授权模型由五个可执行动作组成：**知情、分场景同意、撤回、导出、删除**。五者在产品中必须是同一层级的入口，不能把「删除」藏在设置三级菜单里。

### 4.1 授权矩阵

| 场景 | 授权粒度 | 默认值 | 撤回后的实际效果 |
| --- | --- | --- | --- |
| 导入第三方对话 | 单次导入确认 | 关闭 | 停止新导入；已导入原文按留存策略清除 |
| 生成/更新画像 | 全局开关 | 关闭 | 停止生成新条目；已有条目保留只读 |
| 画像用于专业匹配解释 | 全局开关 | 关闭 | 匹配退化为「基于自陈信息」 |
| 画像摘要展示给某高校 | 每次、每校 | 关闭 | 该校下次请求即不可见 |
| 用于研究（文档 09） | 单独同意，可匿名 | 关闭 | 该用户数据退出研究数据集 |
| 用于产品改进（去标识化） | 单独同意 | 关闭 | 从改进数据集中移除 |

**必须逐项开启，不提供「一键全部同意」按钮** `[已确定]`。一次性勾选会把「知情」变成形式。

### 4.2 第三方 AI 对话导入的专门条款

这是本文最需要写死的部分，因为它是唯一的「把站外高敏感数据搬进站内」的入口 `[设计中]`。

1. **权属声明**：导入前用户须确认「这是我自己与 AI 的对话，不含他人的私人信息」。系统不做事后追责，但必须留下这条确认记录。
2. **本地优先**：解析优先在客户端完成，只有被用户确认保留的片段上传。目标是把上传量压到原文的一小部分。
3. **默认粗粒度抽取**：系统默认只抽取与「兴趣、能力线索、价值观、学习经历」相关的片段，其余内容不解析、不入库。抽取规则对用户可见。
4. **原文与派生分离**：原文 30 天清除（可提前），派生出的画像条目与证据片段可长期保留——因为后者是用户确认过的、且逐条可删的。
5. **不回流第三方**：导入的对话内容不得再发送给任何第三方模型服务用于微调或评测；仅在推理时按需、按片段使用，并在数据处理协议中约定不留存。
6. **可整体撤销**：提供「清除我导入的全部对话」单按钮，一次清空原文与所有由其派生的画像条目，并给出清除完成回执。
7. **不做自动续传**：不提供后台常驻监听，不做「自动同步新对话」。每次导入都是一次显式行为。

### 4.3 导出

导出格式为机器可读的结构化文件（画像条目 + 证据引用 + 置信度 + 时间），附一份人类可读说明。导出不包含他人信息与内部审计字段。`[规划]`

## 5. 画像的证据链与可纠正机制

本节承接 [产品需求文档-考生端](03-产品需求文档-考生端.md) §5.3–§5.6 的画像条目定义，只补充治理侧约束。**分工约定：字段命名与状态机以 03 为准，本文只定义不可让步的约束条件；两侧冲突时，命名改本文、约束改 03。**

### 5.1 字段约定与治理约束

字段名与状态词汇以文档 07 §3.1 / §3.2 为准，本文不重复定义实体，只做两件事：定义两个治理专用字段的语义，并给出三条不可让步的约束。03 §5.3 与本文口径一致；若将来再出现同义异名，以 07 与本文为一致基准。

```text
实体名与字段（以 07 §3.1 为准）：
  entry_id / topic / claim / evidence_refs[] / confidence（低 / 中 / 高）
  first_seen / last_seen / derived_from[] / reviewed_at / status / visibility

状态取值（以 07 §3.2 为准，六态）：
  待验证 | 验证中 | 已确认 | 已否决 | 存在矛盾 | 衰减归档
```

两个治理字段的语义（定义权在本文，03 §5.3 已按此新增）：

- `derived_from[]`：本条目的上游来源，可指向其他条目或证据。只用于纠错时的级联定位，不作为展示字段。
- `reviewed_at`：用户最近一次确认、纠正或否认的时间。用于过期降档判定（见 §8）。它与 `last_seen` 不是一回事——`last_seen` 记录「最近一次被证据支持」，`reviewed_at` 记录「最近一次被人看过并表态」。

**与 03 §5.3 的一致性确认：** 03 对两字段的说明（`derived_from` = 该条目由哪些上游条目 / 证据派生；`reviewed_at` = 用户最近一次确认或纠正的时间）与本节语义一致，**无冲突**；03 已注明这两个治理字段的「定义权在文档 08」，本节即其正式定义出处。

三条治理强制约束 `[已确定]`：

- `evidence_refs` 为空的条目不得写入，也不得展示——与 03 §5.4 第 1 条「无证据不生成」一致。
- `待验证` 是**合法状态**：**「证据不足，暂不判断」必须能被系统说出来**，否则模型会被逼着编一个结论。`存在矛盾` 同样是合法状态，不得为了界面上「好看」而强行消解（见 07 §3.2）。
- 纠正必须**级联**：凡 `derived_from` 指向被纠正条目的下游条目，一律进入 `衰减归档` 或降置信度档，并在界面上告知用户。**不允许出现「上游已被否认、下游仍以高置信度展示」的状态**——与 03 §5.4 第 6 条一致。

### 5.2 纠正流程

```text
用户看到条目（六态见 07 §3.2）
     |
     +--> 认可 ------------------------> 待验证 / 验证中 → 已确认，reviewed_at 更新
     |
     +--> 补充说明 --> 新证据入库 -----> 验证中，可能改置信度档
     |
     +--> 否认 --> 追问"哪里不对"？ --> 已否决（记入负证据，不再复用）
     |                                   |
     |                                   +--> 证据被判定误读 --> 已否决 + 级联降档
     |                                   +--> 证据本身有误 --> 删除证据并级联降档
     |
     +--> 删除 -------------------------> 软删除进回收站（30 天），到期硬删除并级联清理

系统侧：出现反证 --> 存在矛盾（并列展示两组证据，由用户裁定，不自动取新弃旧）
系统侧：长期无新证据 --> 衰减归档（不自动删除）
```

**纠正率是产品质量指标，不是用户流失指标。** 我们反过来要求：上线初期纠正率过低反而说明用户没看懂画像或不信任它。这一点写入 MVP 判据（见 [MVP 实验与验收标准](11-MVP实验与验收标准.md)）。

## 6. 高校侧使用考生画像的硬边界

这是本项目伦理风险最集中的地方：一旦画像能被用于招生筛选，产品就从「帮考生认识自己」变成了「帮高校筛人」，性质完全改变。因此本节写成**三道门 + 一张黑名单**，任何实现都不得绕过 `[已确定]`。

### 6.1 三道门

| 门 | 条件 | 不满足时 |
| --- | --- | --- |
| 门 1：考生主动授权 | 考生在该校的当次会话中开启，且能随时关闭 | 该校侧完全不可见 |
| 门 2：用途限定 | 仅用于「专业探索对话中的解释与推荐」；原始画像与原文片段会话结束即不落库、不可回溯 | 请求被策略层拒绝 |
| 门 3：最小字段 | 只输出白名单字段，不输出原始证据片段 | 降级为通用回答 |

**门 2 的两层含义**（与文档 04 §5.4「撤回后的级联行为」是同一套规则，读法应对得上）：

- **第一层｜会话态，不落库**：高校侧看到的画像内容与原文片段属于会话态数据，会话结束即丢弃，不留副本、不可事后回溯查询。对应 04 §5.4 的「高校侧授权视图立即失效，会话中断，不可再查询」。
- **第二层｜聚合统计，可保留但须去标识化**：允许保留聚合统计（如某专业被咨询的主题分布、问题类型计数），前提是已去标识化且**不可反查个体**（最小分组阈值见 §7.1）。对应 04 §5.4 的「已产生的咨询记录去标识化保留，仅保留主题与问题类型」。

**「可展示」不等于「可作为判断依据」** `[已确定]`：白名单条目可以出现在探索对话的标签或摘要里，但**不得进入推荐理由、排序依据、任何形式的评分或分级**。这条与 07 §3.3「低置信度条目不得出现在推荐理由中」不矛盾——两者约束的是不同表面：08 管「能不能给高校看」，07 管「能不能参与判断」。实现上由输出模板保证，不依赖模型自觉：推荐理由的字段只能来自证据与规则，不得来自画像摘要。

**白名单（可展示）：** 兴趣主题标签、探索记录摘要、`status = 待验证 / 验证中` 且置信度为低或中的画像条目（须连同「仅为初步观察」的标注一起展示）。`visibility` 字段为「可授权给高校」是展示的**必要条件而非充分条件**：仍需门 1 的当次授权。

**黑名单（绝不展示）：** 对话原文、家庭与情绪相关表述、精确联系方式、健康相关信息、由 L3 数据直接派生的任何字段，以及任何 `status = 已否决 / 存在矛盾 / 衰减归档` 的条目。

### 6.2 用途黑名单

以下用途一律禁止，写进高校合作协议而非仅写在文档里：

1. 录取决策、资格审核、专业调剂、奖助评定。
2. 对考生做任何形式的排序或分级。
3. 定向营销、招生触达、二次转授给第三方。
4. 与考生身份信息绑定后长期存储。
5. 用于训练高校侧模型。

配套的审计要求：高校侧的每一次画像读取都生成事件（授权 ID、字段集、用途、时间）。**审计发现越界一次即暂停该校接入**，恢复需重新评审 `[设计中]`。

架构落点与文档 05 对齐：跨侧数据流动必须携带**授权令牌**（`授权 ID + 场景 + 期限 + 字段集`），由接入层统一校验，下游组件不重复判定；令牌过期即失效，不提供自动续期 `[设计中]`。这条是 05 §7 的架构约定在治理侧的对应条款，两侧必须同步修改。

## 7. 脱敏、访问控制与审计

### 7.1 访问控制

| 角色 | 可见范围 | 约束 |
| --- | --- | --- |
| 考生本人 | 全部自己的数据 | 无法访问他人 |
| 监护人（未成年） | 同考生，需绑定关系 | 关系建立需双方确认 |
| 研发（生产环境） | 仅脱敏样本 | 需双人审批、限时、留痕 |
| 数据工程 | 聚合统计 | 最小分组阈值，禁止反查个体 |
| 高校侧 | 白名单字段 | 门 1–3 全部满足 |
| 审计角色 | 审计日志 | 不可读取业务正文 |

「研发可直连生产库查个案」这种便利必须被明确废掉：**生产数据只通过脱敏视图暴露，个案排障走用户授权的临时授权码** `[已确定]`。

### 7.2 脱敏规则

| 字段类型 | 规则 | 例外 |
| --- | --- | --- |
| 姓名 / 学校 | 不可进入分析数据集 | 用户本人可见 |
| 联系方式 | 默认掩码，仅在考生主动发起的会话中解密 | 需二次确认 |
| 对话原文 | 不进入日志、不进入提示词缓存 | 仅解析服务内短时可见 |
| 家庭 / 健康表述 | 入库前过滤，命中即丢弃并记录丢弃计数 | 无 |

### 7.3 审计日志

必须记录：授权变更、数据导出、删除请求与执行、高校侧读取、内部高权限访问、策略拒绝事件。日志采用追加写 + 哈希链保证不可篡改，**且不记录业务正文**——审计日志本身不能成为新的泄露源。

## 8. 数据质量治理

治理不只管「别泄露」，也管「别用错」。

1. **来源标注**：每条数据带来源等级——官方 / 高校授权 / 用户自陈 / 系统推断。四个等级在界面上用不同措辞呈现，**系统推断不得伪装成官方事实**。
2. **冲突处理**：事实类冲突（如招生计划人数）按「来源权威性优先 → 年份新优先 → 人工裁决」；画像类冲突**不自动覆盖**，并列保留并请用户裁决，因为画像本来就该容纳矛盾。
3. **过期数据**：招生章程、招生计划按年度失效，跨年数据只可展示、不可参与计算；画像条目 90 天未复核则置信度自动降一档（分档与衰减口径见 07 §3.3），长期无新证据的条目转入「衰减归档」，需要用户确认或新证据续期 `[设计中]`。
4. **质量指标**：证据引用完整率、条目纠正率、过期数据占比、来源标注缺失率。指标进入文档 09（研究与评估方案）的评估口径。

## 9. 合规风险清单与应对

本节只写监管方向与我们的动作，**不写具体条文编号**；法规原文与最新版本以法务检索为准。本文不是法律意见。

| 风险 | 监管方向 | 我们的应对 |
| --- | --- | --- |
| 未成年人数据 | 对不满十四周岁未成年人须取得监护人同意并制定专门规则；对十四至十八周岁未成年人适用更严格的最小必要与告知要求 | 未成年人显式标识、监护人绑定流程、单独规则文档 `[规划]` |
| 告知同意不充分 | 需真实、准确、完整告知处理目的与方式 | 三问式采集说明、逐场景授权、不设全选按钮 |
| 敏感个人信息 | 需单独同意并具备必要性 | 对话原文按 L3 处理、默认粗粒度抽取、最短留存 |
| 自动化决策 | 需保证透明与拒绝权 | 画像不作为录取依据；提供人工复核与拒绝入口 |
| 数据出境 | 数据出境需评估/标准合同等合规路径 | **试点阶段不做任何数据出境** `[已确定]` |
| 生成式 AI 服务 | 内容安全、标识、训练数据合规 | 输出引用强制回填、拒答策略、不使用用户数据训练 |

## 10. 本文明确不做的事

- 不做数据出境，不做境外模型服务直连。

- 不做「精准招生营销」类能力，即使高校有需求。
- 不把用户对话用于训练任何模型，包括自研模型。
