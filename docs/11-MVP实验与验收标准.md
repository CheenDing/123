## 1. MVP 的定义

**问题：** 早期项目做 MVP，最常见的失败是把它做成「功能少一点的演示版」——能跑通、能给人看、但证明不了任何假设。等演示完了，团队依然不知道这条路成不成立。

**一句话结论：** MVP 是**最便宜的证伪装置**。Phase 1 的 MVP 只回答一件事：**把考生的历史 AI 对话变成可纠正、有依据的个人画像，考生是否认这个画像、并且愿意继续用？** 如果答案是否，那么后面所有的专业发现、志愿决策、高校侧服务都不必做。

由此推出一条设计约束 `[已确定]`：MVP 的每一个功能都必须能对应到某个假设的验证；对应不上的功能一律不进 MVP，哪怕它「看起来很像产品」。

> **取舍：** 我们放弃了「MVP 也要有完整视觉设计与引导流程」的做法。MVP 允许界面粗糙、允许部分环节由研究员人工介入（例如人工核对抽取结果、人工生成部分画像条目，俗称「绿野仙踪法」）。代价是体验数据不可用于产品评价；收益是能在 4 周内拿到关于核心假设的第一手证据，而不是花 8 周做界面。

## 2. 最小可验证假设

MVP 只验证以下四条假设 `[假设]`。每条都必须能被单独证伪。

| 编号 | 假设 | 若为假意味着 |
| --- | --- | --- |
| H-M1 | 考生愿意导入自己的 AI 历史对话，且导入的数据能被解析出足够的有效片段 | 「对话导入」这条入口不成立，需改产品形态 |
| H-M2 | 从片段中能抽出「考生自己没意识到但认同」的画像条目（存在信息增量） | 画像只是把用户已知信息换个说法，产品无增量价值 |
| H-M3 | 考生看到证据链后更信任画像，而不是更困惑 | 证据链设计失败，需重构呈现方式 |
| H-M4 | 考生看到不准确的条目时愿意纠正，且纠正能被系统正确吸收 | 画像无法自我修正，长期会漂移 |

**注意 H-M2 的措辞。** 判据不是「用户说画像很准」（几乎所有人都会礼貌地说准），而是「用户明确表示这条我自己没意识到，但我认同」。前者是社会赞许性，后者才是信息增量。

文档 01 §8 把「画像有效性」列为项目级否决线（该条不成立则项目应转向或停止）。H-M2 与下文的信息增量率，就是这条否决线在 MVP 阶段的操作化——**这也是为什么 MVP 必须包含对照组式的提问设计，而不是只问满意度**。

## 3. 实验设计

### 3.1 招募

以下规模与渠道均为 `[假设]`，需在启动前按实际可得性校准：

- 规模：12–20 名考生，另访谈 3–5 名家长（家长不参与产品操作，只做访谈）。
- 画像：高三在读或刚经历志愿填报的考生；有使用 ChatGPT / Claude / DeepSeek 等 AI 工具的历史；自愿参与。
- 渠道：通过学校社团、教师推荐、公开招募表单。**不得以「提高录取率」「精准推荐」为招募话术**，招募文案须经复核，避免制造效果预期。
- 未成年人：按文档 08 §9.2 的假设，MVP 阶段仅招募已满 18 周岁或监护人现场陪同的考生。
- 排除项：近期有明确心理困扰、或明确表示不愿分享对话者（尊重其不参与）。

### 3.2 流程

```text
 第 0 天          第 1 天              第 3–5 天            第 2 周           第 4 周
+--------+     +-------------+      +--------------+     +---------+      +-----------+
| 招募与 |---->| 授权与导入  |----->| 画像生成与   |---->| 自主使用 |---->| 回访与    |
| 知情同意|     | 对话（可跳过）|     | 证据链查看   |     |（不干预） |     | 深度访谈  |
+--------+     +-------------+      +--------------+     +---------+      +-----------+
                     |                     |                   |                |
                  记录放弃率          记录纠正行为        记录留存与使用     记录复述能力
```

- 每名参与者至少 3 次接触：导入与首次查看（约 45 分钟）、第 1 周简短回访（10 分钟）、第 4 周深度访谈（40 分钟）。
- 全程有研究者在场但不引导操作，只在用户卡住时记录「卡点」而不是帮忙点。

### 3.3 访谈脚本要点

**不要问「你觉得好不好用」**——这类问题只会得到礼貌的肯定。要问行为与具体记忆：

1. 「上一次你打开它是什么时候？当时想干什么？」（真实使用而非声称使用）
2. 「有没有哪一条画像，你觉得它说错了？当时你做了什么？」（纠正行为）
3. 「如果现在让你给同学解释系统对你的判断，你会怎么说？」（理解度与可复述性）
4. 「这条结论是从哪句话来的，你还记得吗？」（证据链是否真的被感知）
5. 「如果明天这个功能消失了，你会想念它吗？会想念哪一部分？」（价值密度）
6. 「导入对话的时候，你最担心什么？」（信任与顾虑）

### 3.4 巴纳姆效应对照（关键设计）

文档 01 §8 与文档 00 都要求：画像认可率必须显著高于「随机生成的画像描述」，否则用户认可的只是「说得挺像那么回事」。因此 MVP 必须内置对照条件，否则 H-M2 无法判读 `[设计]`：

1. 在用户查看自己画像时，**混入 2 条来自其他参与者（或基于通用模板生成）的画像描述**，与真实条目随机排序，不告知哪条是哪种。
2. 请用户对每条独立判断：「这说的是你吗？（是 / 部分 / 不是）」以及「这条是你自己没意识到但认同的吗？」
3. 计算两组认可率差值。

判定：真实条目与对照条目的「是」占比差值 ≥ 15 个百分点 `[假设]` 才算有意义；差值 < 5 个百分点时，H-M2 实质不成立——用户对任何描述都愿意说「准」。这条设计成本很低（不改产品，只改呈现顺序），但决定了整个 MVP 的结论是否有意义。

对照组数据同时用于校准 §4 的信息增量率基线，避免把「礼貌性认同」算成增量。

## 4. 成功指标与否决线

**先明确层级：这里的「成功线 / 否决线」是阶段判定，不是产品验收。** 文档 03 §11 的 `AC-01`–`AC-08`（考生端）与文档 04 §9.1 的 `AC-U-01`–`AC-U-05`（高校端）是**每迭代都要跑的回归门**，回答「这个功能做对了吗」；本文的成功线与否决线是 **Phase 1 的阶段判定**，回答「这条路还值不值得走下去」。两者不互相替代：评审用本文判方向，研发用 03 / 04 的 AC 判回归。

- **回归门示例：** 03 的 `AC-03`「纠正与级联留痕」——每次纠正产生负证据、下游 `derived_from` 条目同步失效或降档、界面有「已同步更新」告知。它正是本文「纠正完成率 ≥ 70%」与「严重错误率」两项指标的**实现前提**：若 AC-03 不通过，纠正类指标全部无效，阶段判定也不得采信。
- **复用口径：** 本文凡涉及「条目有证据」「纠正生效」「无越界表述」的指标，回归口径直接复用 03 的 `AC-01` / `AC-02` / `AC-03` / `AC-08`；高校侧指标本 MVP 不测，回归口径预留给 04 的 `AC-U-01` / `AC-U-02` / `AC-U-04`。
- **不允许的用法：** 不得用「AC 全绿」代替阶段判定（功能做对了，不代表假设成立），也不得用「MVP 达标」代替回归门（一次实验通过，不代表每个迭代都稳定）。

指标分三层：**必须达到（否则失败）**、**期望达到**、**观察项**。所有阈值均为 `[假设]`，Phase 1 结束后据实校准。

| 指标 | 定义 | 测量方式 | 成功线 | 否决线 |
| --- | --- | --- | --- | --- |
| 导入意愿率 | 同意导入 / 受邀人数 | 行为记录 | ≥ 60% | < 30% |
| 解析可用率 | 能抽出 ≥ 3 条有效片段的导入 / 全部导入 | 人工核对 | ≥ 70% | < 50% |
| 信息增量率 | 用户标记「没意识到但认同」的条目 / 全部条目 | 逐条标注 | ≥ 25% | < 10% |
| 巴纳姆差值 | 真实条目认可率 − 对照条目认可率 | 混排盲评（§3.4） | ≥ 15 个百分点 | < 5 个百分点 |
| 严重错误率 | 用户判定「完全不对」的条目 / 全部条目 | 逐条标注 | ≤ 10% | > 25% |
| 纠正完成率 | 提出异议并完成纠正流程 / 提出异议数 | 行为记录 | ≥ 70% | < 40% |
| 证据定位率 | 30 秒内成功定位某条画像对应原文 / 被测条目 | 现场任务测试 | ≥ 80% | < 50% |
| 第 2 周留存 | 第 2 周仍主动打开 / 全部参与者 | 行为记录 | ≥ 50% | < 20% |
| 复述能力 | 能用自己的话准确复述 2 条画像及其理由 / 全部参与者 | 访谈编码 | ≥ 60% | < 30% |
| 伦理否决 | 明确表示「被贴标签 / 不适 / 被冒犯」的人数 | 访谈 + 主动反馈 | 0 | ≥ 2 人 |

**「伦理否决」是一票否决项**，不受其他指标影响。出现 2 人及以上明确不适，无论数据多好看，都要停下来重新设计呈现方式与措辞。

## 5. 什么结果说明这条路不成立

这是本文最有价值的部分。以下五种结果模式，分别指向不同的结论——**关键是区分「产品没做好」与「假设是错的」**，因为二者的应对完全不同。

| 结果模式 | 现象 | 判读 | 应对 |
| --- | --- | --- | --- |
| A. 入口失效 | 导入意愿率 < 30%，且访谈中普遍表达对隐私的强烈顾虑 | 不是话术问题，是「交出 AI 对话」这个动作本身越过了多数人的心理门槛 | **pivot**：改为「受控导入」（用户挑选 3–5 段对话手动粘贴，而非批量解析）或改为结构化自陈 |
| B. 无增量 | 信息增量率 < 10%，绝大多数条目用户说「这我本来就知道」 | 从对话里抽出的只是用户已自陈的信息，长期交互没有产生新理解 | **stop 或 pivot**：要么放弃「画像」叙事，只做「信息整理 + 专业解释」；要么重新设计抽取目标 |
| C. 高错误 | 严重错误率 > 25%，且纠正率低 | 抽取质量差只是表层；真问题是用户不愿花力气纠正，说明画像对他不重要 | 若纠正率也低 → **stop**；若错误高但纠正意愿高 → **继续迭代**（这是产品问题，不是假设问题） |
| D. 证据链反噬 | 证据定位率低，且访谈出现「看到原文反而觉得你们在过度解读」 | 把证据摆出来暴露了推断的脆弱性，透明度反而降低了信任 | **pivot**：从「展示原文」改为「展示推断依据的结构化摘要 + 可展开原文」 |
| E. 用完即走 | 首次体验正面，第 2 周留存 < 20% | 画像是一次性好奇消费，没有形成持续使用的理由 | **pivot**：把画像从「结果」变成「过程」，绑定到具体的专业探索任务上 |
| F. 礼貌性认同 | 信息增量率看似达标，但巴纳姆差值 < 5 个百分点 | 用户对任何画像描述都会说「准」，全部正面反馈都不构成证据 | **stop 重设计**：先解决「如何让用户能分辨准与不准」，再谈画像价值 |

**特别提醒：** 出现 B 或 C 时，团队最容易的自我安慰是「样本太小 / 用户不会用 / 需要更好的模型」。这三句话可能是对的，但**在 MVP 阶段不能作为解释**——MVP 的作用正是在低成本条件下判断方向，如果必须靠「更好的模型」才能成立，那么这个假设在当期资源下就是不成立的。

## 6. MVP 功能清单

| 必须有（不做就无法验证） | 可以没有（有更好，没有不影响判读） | 明确不做 |
| --- | --- | --- |
| 授权 / 撤回 / 删除流程 | 精美视觉与动效 | 志愿方案生成 |
| 对话导入（至少支持 1 种导出格式） | 多轮自我探索引导 | 录取风险计算 |
| 证据片段抽取与展示 | 画像历史版本对比 | 高校侧任何功能 |
| 画像条目 + 置信度 + 证据链查看 | 分享卡片 | 多省数据接入 |
| 纠正与级联失效 | 移动端适配 | 账号体系与社交功能 |
| 研究埋点与访谈记录工具 | 多语言 | 付费与运营功能 |

**「必须有」列表的最后一项容易被忽略：研究埋点。** 如果 MVP 不能准确记录「用户在第几秒点了什么、对哪条画像停留最久、在哪里放弃」，那么实验结束后只能靠访谈回忆，判读质量会大幅下降。

## 7. 技术验证点

MVP 同时承担四个技术验证任务，每个都有明确的可测口径：

| 验证点 | 具体问题 | 测法 | 通过口径 |
| --- | --- | --- | --- |
| 对话导入解析 | 各家导出的格式差异有多大？ | 收集真实导出样本，统计格式分布与解析成功率 | 主流格式解析成功率 ≥ 60% `[假设]` |
| 兴趣抽取 | 抽出的片段是否真的与兴趣/能力相关？ | 人工核对 100 条片段，标注相关/无关/误读 | 相关率 ≥ 70%，误读率 ≤ 15% `[假设]` |
| 证据链呈现 | 用户能否把结论和原文对上？ | 现场定位任务 + 眼动或点击路径观察 | 30 秒定位率 ≥ 80% |
| 画像纠正 | 纠正后系统是否真的改了？ | 检查纠正后的条目状态与派生结论失效情况 | 级联失效 100% 正确，无残留 |

## 8. go / pivot / stop 判据

```text
                    +----------------------+
                    | 伦理否决 >= 2 人 ?   |
                    +----------+-----------+
                          是 /              \ 否
                           v                 v
                    +-----------+    +------------------+
                    | STOP 重设计|    | 导入意愿 >= 60% ?|
                    +-----------+    +--------+---------+
                                        否 /        \ 是
                                         v            v
                                  +-----------+  +----------------+
                                  | PIVOT 入口|  | 信息增量 >= 25%?|
                                  +-----------+  +--------+-------+
                                               否 /        \ 是
                                                v            v
                                         +-----------+ +---------------+
                                         | PIVOT 叙事| | 证据链与纠正  |
                                         | 或 STOP   | | 是否达标 ?    |
                                         +-----------+ +-------+-------+
                                                          否 /   \ 是
                                                           v       v
                                                    +-----------+ +--------+
                                                    | 迭代一轮  | |  GO    |
                                                    | (非 pivot)| | 进 P2  |
                                                    +-----------+ +--------+
```

**先判巴纳姆：** 巴纳姆差值 < 5 个百分点时，无论其他指标多好看，一律进入 STOP 重设计（见 §5 模式 F）。理由很简单：对照失效意味着所有「用户认可」类指标都不可信，继续解读其余数字只会自我说服。

| 判定 | 触发条件 | 动作 |
| --- | --- | --- |
| **GO** | 伦理否决 0；导入意愿 ≥ 60%；巴纳姆差值 ≥ 15 个百分点；信息增量 ≥ 25%；严重错误 ≤ 10%；证据定位 ≥ 80%；第 2 周留存 ≥ 50% | 通过 G1，进入 Phase 2；结论写入研究报告 |
| **迭代** | 核心指标（增量、错误率）达标但体验类指标（证据定位、留存）未达标 | 允许一轮针对性迭代（4 周内），不得扩大范围；迭代后仍不达标转 pivot |
| **PIVOT** | 入口或叙事假设被证伪（模式 A、B、D、E），但团队仍相信「个人理解」这个方向 | 改变产品形态（受控导入 / 结构化摘要 / 绑定任务），保留证据链与授权机制，重做一轮 MVP |
| **STOP** | 伦理否决 ≥ 2 人；或 pivot 后核心指标仍不达标；或用户明确表示该能力无价值且无替代形态 | 停止 Phase 1 方向，向愿景层面回退重新判断项目定位 |

**决策纪律：** 判据在实验开始前写死，实验结束后不得修改阈值。若确实要改，必须在报告中同时公布原阈值与修改理由——这是防止团队自我说服的唯一办法。

## 9. 与文档 09 的对应

MVP 的指标不是自创的，直接取自研究方案的 RQ1 与 RQ2：

| MVP 指标 | 对应研究设计 | 说明 |
| --- | --- | --- |
| 信息增量率 | RQ1 / H1a | 同一构念，MVP 用小样本快速估计 |
| 严重错误率、纠正完成率 | RQ2 的效度威胁控制 | MVP 提供初步错误率，正式测量在纵向研究 |
| 第 2 周留存 | RQ1 的跨时间复现 | 行为的粗粒度代理 |
| 证据定位率、复述能力 | RQ3 的可解释性 | MVP 只测「能不能对上」，不测「推荐准不准」 |

MVP 与正式研究的关系是：**MVP 负责快速判断方向，正式研究负责给出可发表的证据。** 二者的样本、周期、严谨度不同，结论不可互相替代，报告中必须分开陈述。

## 10. 伦理与合规前置条件

MVP 也必须完整走文档 08 的流程，不得以「只是内测」为由简化 `[已确定]`：

1. 知情同意书（含数据用途、留存、退出方式）签署后方可导入。
2. 导入是可跳过的，拒绝导入不影响参与后续访谈。
3. 随时可退出，退出后按删除流程处理，且不影响任何权益。
4. 访谈录音需单独授权，且录音在转写后 30 天内删除。
5. 实验数据不用于训练模型；如后续要用于产品改进，须重新取得同意。
