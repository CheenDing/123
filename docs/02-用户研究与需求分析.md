## 1. 本文回答什么，以及用什么证据回答

**结论先行：** 考生在志愿这件事上做不好，主因不是「分数数据不够全」，而是三层不对称叠加——数据不对称、语义不对称、自我不对称。现有工具几乎全部把它当成「匹配问题」处理，于是只解掉了第一层，把最难的一层留给了用户在最后三天独自面对。

### 1.1 四个研究问题

1. 考生实际**做了什么**（行为链），而不是他们声称在意什么。
2. 现有方案在**哪一步**失效，失效是能力问题还是设计取向问题。
3. 哪些需求是「提出来但没被满足」，哪些是「根本没被提出来」——后者才是产品机会。
4. 高校侧需求与考生侧需求是否**结构性冲突**；如果冲突，边界画在哪里。

### 1.2 方法与证据等级

证据来源限定为四类，并明确声明：**没有做统计抽样、没有做问卷、没有做正式访谈**。因此本文不出现任何比例、规模类数字；所有关于「用户会怎样」的陈述，要么是可观察行为的归纳，要么标记为 `[假设]` 并给出验证方式。

| 等级 | 来源类型 | 用法 | 能否支撑「已确定」 |
| --- | --- | --- | --- |
| L1 | 公开可查的考生自述与讨论（问答社区、内容平台评论、求助帖） | 描述行为链与话语方式 | 支撑「这类行为存在」，不支撑「有多少人」 |
| L2 | 高校公开发布的招生章程、招生简章、选科要求、转专业政策 | 描述高校侧工作流与约束 | 支撑流程性事实 |
| L3 | 方法论文献（如 Designing Your Life） | 设计依据 | 需按规范 §5.2 注明来源 |
| L4 | 基于以上材料的场景推演 | 提出待验证假设 | 仅支撑 `[假设]` |

### 1.3 本文不做的事

不做人口统计建模；不做心理诊断或人格分类（对心理状态的描述只作为**处境**，不作为**个体属性**判断）；不逐条对标竞品功能，只复盘其**机制假设**——逐条对标会诱导我们抄功能清单。

## 2. 考生侧：五种真实处境

**本节方法说明：** 不使用「用户画像」这类虚构角色卡片。志愿填报的差异主要由**处境**决定而非性格；同一人在不同处境下会做出相反选择。因此下文单位是「处境 + 行为链」。

### 2.1 处境 A：信息饥渴型

成绩中上，家庭无相关经验，老师只能给「报稳妥一点」这类原则性建议。

**行为链：** 出分前一周密集搜索 → 刷「XX 分能上什么」类短视频 → 加家长群与学长群 → 收藏大量截图但不整理 → 打开志愿工具输入分数，得到一屏学校列表 → 对专业名称没有判断力 → 按「听起来不错」「城市还行」排序 → 提交。

**关键观察：** 信息摄入量并不低，但信息**从未被结构化到自己身上**——收集的是「学校有哪些」，缺的是「我适合什么」。

### 2.2 处境 B：家长代决策型

家庭由父母主导，话语核心是「不浪费一分」；考生参与度低，常以沉默或事后反悔表达异议。

**行为链：** 家长建群、听课、做表格 → 考生被问「想学什么」，答「都行」→ 家庭会议按「分数—学校层次」排序 → 考生表达模糊偏好，被「这个不好就业」驳回 → 按家长方案填报。

**关键观察：** 真正用户是**家庭**而非个体。只面向考生设计会被绕过；只面向家长设计会强化「分数最大化」，与「先认识自己」冲突。**这是核心设计张力**，处理见 §8.3。

### 2.3 处境 C：复读生

经历过一次完整填报，对流程不陌生，但对「再来一年」的沉没成本高度敏感，风险偏好显著保守。

**行为链：** 复用上一年志愿表做底稿 → 只做小幅调整 → 对「冲」（Reach）的档位极度犹豫 → 反复核对招生章程里的单科要求与体检限制 → 更信任「上一年真的被录取过的人」而非工具。

**关键观察：** 需求不是更多信息，而是**降低后悔概率**；对「你为什么推荐这个」的解释要求高于首次填报者。这支持把可解释性列为第一优先级而非加分项。

### 2.4 处境 D：竞赛生与专项路径考生

路径依赖强，规则复杂度高（强基计划、专项计划、综合评价等通道并存，时间窗口与录取规则各异）。

**行为链：** 依赖教练、学长或家长中「懂行的人」→ 在多通道间取舍 → 填报优先保通道策略而非专业偏好 → 高考后对「如果不走这条路会选什么」缺乏准备。

**关键观察：** 他们是**规则复杂度**的受害者。最需要的是「我的约束条件是什么」的结构化清单，而不是更多搜索结果。

### 2.5 处境 E：资源薄弱地区考生

家庭中无大学生，学校缺乏专职生涯指导，网络可达但**辨识成本高**。

**行为链：** 主要依赖班主任口传经验 → 对专业名称望文生义 → 易受「热门专业」话术影响 → 不了解转专业、辅修、跨专业升学等后续路径，把一次选择当终局。

**关键观察：** 「专业名称 → 实际学什么」的翻译价值最高；同时最需要「这不是终局」这一认知。

### 2.6 横向对照

| 处境 | 核心焦虑 | 现有方案失效点 | 我们的介入点 |
| --- | --- | --- | --- |
| A 信息饥渴 | 怕选错，无判断标准 | 只给列表，不给依据 | 把信息折叠到个人画像上 |
| B 家长代决策 | 怕浪费分数 | 只服务单一用户，承载不了家庭协商 | 画像的可分享讨论视图 |
| C 复读生 | 怕后悔 | 结果不可解释，不敢信 | 每条建议给证据与不确定性 |
| D 竞赛/专项 | 怕规则理解错 | 规则散落多份文本 | 约束条件结构化清单 |
| E 资源薄弱 | 怕望文生义 | 专业介绍停留在宣传语 | 培养方案翻译为学习体验 |

> 上表是设计用对照工具，不构成对任何群体的规模判断。

## 3. 核心痛点：三层信息不对称

### 3.1 第一层：数据不对称

分数、位次、招生计划、选科要求、招生章程中的单科与体检限制，分散在省级考试院、高校官网与纸质材料之间，口径不一、年份不一。

**这一层已被现有工具大量解决，且相当成熟。** 我们不以「数据更全」为差异化主张——这是刻意取舍，理由见 §4.3。

### 3.2 第二层：语义不对称

考生看到一串专业名称，而名称与实际培养内容之间没有稳定对应：同名专业在不同高校的培养方案可能差异显著，部分名称因历史沿革而字面失真。考生想知道「这四年上什么课、被要求具备什么能力」，公开材料通常只给培养目标表述与课程列表。

**缺口不是「没有数据」，而是「数据没被翻译成可判断的形态」。**

### 3.3 第三层：自我不对称

考生不知道自己要什么，也不知道「要什么」这件事可以被系统探索。特殊性在于：**用户不会主动提出这个需求**。他提出的是「帮我看看能上什么」，因为他不知道还有另一种问法。

**这是现有方案覆盖最少、也最难做的一层**，它的价值不在「给出答案」，而在「提出更好的问题」。

### 3.4 痛点强度与可解性

| 痛点 | 感知强度 | 现有覆盖 | 我们的可解性 | 判断 |
| --- | --- | --- | --- | --- |
| 数据分散、口径不一 | 高 | 高 | 中（依赖数据源接入） | 跟进，不作主张 |
| 专业内容看不懂 | 中高 | 低 | 高（依赖内容结构化） | 主攻 |
| 不知道自己要什么 | 低（未被提出） | 极低 | 中（依赖长期交互） | 主攻，需教育用户 |
| 怕后悔、怕担责 | 高 | 低 | 中（依赖可解释性） | 主攻 |
| 家庭意见不一致 | 中 | 无 | 中（依赖协作视图） | 次优先 |

## 4. 现有方案的能力边界

### 4.1 三类现有方案

分数线查询工具（解决数据可达性）、填报推荐算法（输入分数，输出冲稳保列表，解决初筛效率）、内容社区与付费咨询（以人的经验为供给）。

### 4.2 共同的机制假设

三者共享同一个隐含假设：**用户偏好已知且稳定，志愿填报是在已知偏好下求最优匹配**。

这个假设在实践中不成立：偏好往往在看到选项之后才被塑造，且极易受表述方式影响。把「探索偏好」从产品中删掉，等于把最难的工作推回用户，并用一个漂亮的列表掩盖它的缺失。

### 4.3 取舍一：不参与分数换算工具的精度竞赛

**放弃什么：** 不与现有工具在「位次换算精度」「院校覆盖数量」上竞争。

**为什么：** 其一，该层边际收益已很低且高度依赖数据授权，早期项目没有优势；其二，精度竞赛会把重心拉向「算得准」，而我们的主张是「想得清」；其三，宣称精度会滑向效果承诺，触碰规范 §1.3 红线。

**代价：** 短期「查数据」体验弱于成熟工具。缓解方式是明确告知数据口径与覆盖范围，缺失时如实显示，不用估算值填空。

## 5. 关键洞察：为什么「先认识自己」在填报场景中缺失

### 5.1 四个结构性原因

1. **时间结构**：出分到填报截止的窗口极短，用户处于「必须马上决定」状态，需要沉淀的探索会被挤压。
2. **评价结构**：十二年教育的反馈几乎全部来自分数，考生缺乏「我对什么感兴趣」的有效反馈经验与描述词汇。
3. **话语结构**：家庭决策中「分数最大化」可量化、可争论；「我好像喜欢做这个」不可量化、易被驳回。
4. **工具结构**：现有工具的输入框只有一个——分数。**输入框决定了用户如何理解问题。**

### 5.2 一个反直觉推论

用户不是不需要自我探索，而是**没有成本足够低的入口**。一次性量表成本低但结论空泛；深度咨询有效但昂贵且不可扩展。中间地带——「在自然对话中被逐步理解」——恰好是 LLM 与长期交互记忆能覆盖的。

### 5.3 从「一次性量表」转向长期交互记忆

一次性量表测量的是用户在被问的那一刻对自己的叙述，而非行为中暴露的偏好。长期交互记忆可积累三类信号：主动谈论的主题、任务中的实际选择、对推荐结果的反应（接受、忽略、反驳）。可靠性依次上升，因为它们离真实行为越来越近。

这也是我们把**证据**而非结论作为产品核心对象的原因：**结论会过期，证据不会。**

### 5.4 待验证假设

| 编号 | 假设 | 验证方式 | 阶段 |
| --- | --- | --- | --- |
| H1 | 考生愿为「更懂自己」付出 3 次以上、每次 10 分钟以上的对话 | 统计完成第 3 轮对话的比例与中断点分布 | Phase 1 |
| H2 | 带证据的画像条目比不带证据的结论更易被接受并纠正 | 对照实验，观察纠正率与信任自评 | Phase 1 |
| H3 | 家长愿接受「讨论视图」而非要求完整画像 | 访谈 + 授权行为观察 | Phase 2 |

## 6. 需求分层

### 6.1 分层方法

Must / Should / Could 三层，每项标注**现有替代**与**差距**。判断依据只有一条：若这项需求不被满足，用户是否会退回现有方案？会退回的是 Must，不会的是 Should。

### 6.2 考生侧需求清单

| 编号 | 需求 | 层级 | 现有替代 | 差距 | 状态 |
| --- | --- | --- | --- | --- | --- |
| R-C-01 | 把专业信息翻译成「学什么、怎么学」 | Must | 官网培养方案、简章 | 未翻译为学习体验，跨校不可比 | `[规划]` |
| R-C-02 | 每条推荐都说明「为什么是你」 | Must | 无 | 只给匹配度，不给依据 | `[设计中]` |
| R-C-03 | 被持续理解，而非每次从零开始 | Must | 无 | 每次填报重答同样的问题 | `[设计中]` |
| R-C-04 | 画像可查看、可纠正、可删除 | Must | 无 | 用户对「系统怎么看我」不可见 | `[设计中]` |
| R-C-05 | 硬性规则（选科、体检、单科要求）不出错 | Must | 人工核对章程 | 易漏，无系统性校验 | `[设计中]` |
| R-C-06 | 冲稳保三档方案 + 风险说明 | Must | 推荐工具 | 有分档，无风险叙述 | `[设计中]` |
| R-C-07 | 探索式对话，帮助澄清兴趣 | Should | 付费咨询 | 贵、不可扩展 | `[设计中]` |
| R-C-08 | 人生设计类练习（Workview / Lifeview 等） | Should | 书籍自助 | 无引导、无沉淀 | `[规划]` |
| R-C-09 | 家庭协商用的讨论视图 | Should | 线下争论 | 无结构化工具 | `[规划]` |

### 6.3 排序逻辑

不按「用户说得多急」，而按三项乘积：**缺口大小 × 相对现有方案的可验证优势 × 依赖可满足性**。R-C-02 与 R-C-04 最前，因为它们是缺口最大、也是唯一能建立结构性优势的一层（证据链 + 可解释性）。R-C-01 属 Must 但次之，因高度依赖内容建设。

## 7. 高校侧：招生办的真实工作流与约束

**结论先行：** 招生办不缺宣传渠道，缺的是「考生到底在问什么」的反馈信号，以及「同一个问题被问一千遍」的重复劳动。高校端的价值主张因此不是「再做一个官网」，而是「把咨询变成可积累的知识资产」。

### 7.1 一年周期与时间错配

```text
 9月     10月     11月     12月     3月      6月      7月      9月
  |        |        |        |        |        |        |        |
招生复盘  章程起草  选科要求  计划编制  强基/专项  高考    出分后    新生
与总结    与报审    上报      与核对    报名期    考试    咨询高峰  入学
  |        |        |        |        |        |        |        |
内容更新窗口 <--------+        |        +--> 话术准备 --> 高峰应答 --> 复盘
```

**观察：** 咨询高峰极短、人力极度紧张，而内容生产窗口（9 月至次年 3 月）相对宽裕。**必须在淡季把知识准备好，在旺季只做检索与兜底**——这是高校端的第一个设计约束。

### 7.2 三类角色

| 角色 | 主要动作 | 约束 |
| --- | --- | --- |
| 招生办工作人员 | 制定口径、审核内容、应对高峰咨询 | 人力有限，不能超出口径承诺 |
| 院系联络人 | 提供专业内容与培养特色说明 | 表述习惯不统一，专业性强但不愿写长文 |
| 在校生志愿者 | 回答学习体验类问题 | 视角真实但无权代表学校表态 |

### 7.3 高校侧需求清单

| 编号 | 需求 | 层级 | 现有替代 | 差距 | 状态 |
| --- | --- | --- | --- | --- | --- |
| R-U-01 | 结构化知识库，一次维护多处复用 | Must | 官网 + 纸质简章 | 重复维护，口径易漂移 | `[设计中]` |
| R-U-02 | 招生 Agent 承接高频重复咨询 | Must | 电话 + 群 + 现场 | 高峰人力不足，质量不稳 | `[设计中]` |
| R-U-03 | 知道考生在问什么、哪些答不上来 | Must | 无系统化手段 | 只有零散印象 | `[规划]` |
| R-U-04 | 内容发布前的口径与合规校验 | Must | 人工审阅 | 依赖个人经验，易漏 | `[设计中]` |
| R-U-05 | 考生授权下的个性化专业匹配 | Should | 无 | 只能做统一话术 | `[规划]` |
| R-U-06 | 咨询分析报表（脱敏聚合） | Should | 手工统计 | 成本高、不及时 | `[规划]` |
| R-U-07 | 多角色协作与权限分级 | Should | 共享文档 | 无留痕、无责任边界 | `[规划]` |

### 7.4 与考生侧的结构性冲突

冲突点只有一个但很关键：**高校希望尽可能多获得考生信息以提升转化，考生希望尽可能少暴露信息以保持选择自由。**

这不能靠「更聪明的产品设计」消解，只能靠**制度性边界**：画像的跨侧使用必须由考生主动、逐项授权，限定用途与期限、可撤回，且明确禁止用于录取决策。边界在 [产品需求文档-高校端](04-产品需求文档-高校端.md) 第 5 章展开，在[数据治理隐私与合规](08-数据治理隐私与合规.md)中作为治理条款固化。

## 8. 需求优先级与取舍

### 8.1 优先级分布

```text
     低 <-------------- 实现成本 ---------------> 高
高 |  R-C-02 可解释推荐   R-C-04 画像可控
   |  R-C-05 规则校验     R-U-02 招生 Agent

   |  ------------------------------------------
```

R-C-04、R-U-03 成本偏低而优先级高，应尽早做。

### 8.2 取舍二：放弃「录取概率百分数」

**放弃什么：** 任何形如「录取概率 78%」的输出。

**为什么：** 其一，概率数值需要分布假设，分省分专业样本量常不足以支撑可靠估计，精确到个位是虚假的确定感；其二，用户会把它当承诺，落空则信任一次性崩塌；其三，它会把讨论从「这条路适不适合我」拉回「这个数准不准」。

**替代方案：** 输出**风险等级 + 依据 + 不确定性来源**，例如「该专业组近年招生计划波动较大，位次参考可靠性中」，并列出数据口径与年份。用户得到判断力，而不是一个数字。

### 8.3 取舍三：家庭场景只做讨论视图，不做家长端

**放弃什么：** 不做面向家长的独立产品端。

**为什么：** 独立家长端会推向「分数最大化」的单目标优化，与三条基本原则冲突；完全忽略家长，产品又会在决策现场被绕过。

**折中：** 考生可生成**只含指定条目**的分享视图，家长看到「考生同意披露的画像摘要 + 可标注的分歧点」，而非完整画像。

**暂不服务的对象：** 初中生生涯规划、考研与留学申请、在职人员职业转型。方法论可复用，但决策约束与数据源不同，早期分散精力会削弱主场景深度。
