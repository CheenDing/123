## A. 高考与招生制度术语

这些是讨论志愿填报时绕不开的制度词汇。如果你已经很熟悉，可直接跳到 §B。

| 术语 | 英文 | 解释 |
| --- | --- | --- |
| 位次 | Rank | 考生在本省同科类考生中的排序位置。**比分数更可比**，因为每年试卷难度不同，但位次的含义相对稳定。志愿分析的主要基准。 |
| 一分一段表 | Score Distribution Table | 教育考试院公布的"某分数对应多少人、累计多少人"的统计表，是分数与位次互相换算的依据。 |
| 批次 | Admission Batch | 录取的先后轮次，如本科提前批、本科批、专科批。不同批次可填的院校范围不同。 |
| 院校专业组 | Major Group | 新高考省份的投档单位。一所院校被拆成若干"专业组"，组内专业有相同的选科要求；投档到组，再在组内分专业。**这是新高考志愿的核心单位**，理解它才能理解"服从调剂"。 |
| 选科要求 | Subject Requirements | 某专业（组）要求考生必须选考哪些科目。如"物理+化学"。**选科不符则无法投档**，这是硬约束，必须由确定性程序校验。 |
| 新高考 3+1+2 | — | 一种选科模式：语数外 3 门必考，物理/历史 2 选 1，其余 4 科选 2。各省方案不同，本文档统一称"新高考"。 |
| 招生计划 | Admission Plan | 某高校某专业在某省当年计划招收的人数。逐年编制，是当年录取不确定性的主要来源。 |
| 招生章程 | Admission Charter | 高校公布的具有法律效力的招生规则文件，含身体条件、单科成绩、外语语种、专业级差等特殊要求。**这是最容易被忽略、也最容易导致退档的部分。** |
| 投档 / 退档 | Filing / Rejection | 投档：省考试院把档案投给高校；退档：高校审阅后不予录取并把档案退回。退档后本批次通常无法再投。 |
| 冲稳保 | Reach / Match / Safety | 志愿方案中三类院校的通俗划分：冲（录取位次高于自己，有风险）、稳（与自己位次相当）、保（明显低于自己位次，兜底）。 |
| 服从调剂 | Obey Adjustment | 是否同意在投档的专业组内被调剂到未填报专业。不同意则可能被退档。 |
| 平行志愿 | Parallel Preferences | 一种投档规则：按"分数优先、遵循志愿、一轮投档"处理。志愿顺序仍然重要。 |
| 强基计划 / 综合评价 | — | 特殊类型招生渠道。**本项目 Phase 1–4 不覆盖**，明确排除。 |

## B. 产品与用户概念 ★

| 术语 | 英文 | 解释 | 详见 |
| --- | --- | --- | --- |
| ★ 个人画像 | Personal Profile | 系统对"你是一个怎样的人"的动态理解，由兴趣主题、关注领域、能力线索、价值观、职业期待等条目构成。**不是测评结果，不是人格标签**，而是一组带证据的判断集合。 | 03、06 |
| ★ 证据 | Evidence | 支撑某条画像判断的原始材料片段（一段对话、一篇日记、一次任务记录），附时间与来源。用户可点开查看。 | 07、08 |
| ★ 置信度 | Confidence | 系统对该条判断的把握程度，分档表示（低/中/高），并随新证据更新。**不是概率承诺**。 | 07 |
| ★ 长期交互记忆 | Long-term Interaction Memory | 跨会话保留的、关于用户的连续记忆，使系统在数月尺度上仍然"记得你"。与"聊天记录"的区别是：它是被结构化、被检索、被遗忘机制管理的。 | 06 |
| ★ 自我探索 | Self Discovery | 通过对话与练习认识自己的过程，包含苏格拉底式访谈、工作观/人生观探索、美好时光日志、奥德赛计划。 | 03 |
| ★ 专业发现 | Major Discovery | 把个人画像与学科知识、专业培养要求建立关联，产出多条候选路径的过程。区别于"专业推荐"——前者给路径，后者给结论。 | 03 |
| ★ 智能志愿决策 | Admission Decision | 在完成探索后进入的实际填报环节：位次分析、计划核对、风险区间评估、冲稳保方案生成、多目标优化、章程校验。 | 03 |
| ★ 降级模式 | Degraded Mode | 当用户跳过"自我探索"直接要推荐时，系统以纯分数匹配方式工作，但明确告知缺少"对人的理解"这一层输入。这是产品诚实性的体现。 | 01、03 |
| ★ 试点场景 | Pilot | 东北大学作为本项目高校侧能力的验证场景。**属于合作设想，不是校方官方服务。** | 04 |

## C. 方法论术语（人生设计）

源自斯坦福大学 *Designing Your Life* 方法论。我们在产品中借用其框架，做了适配改造。

| 术语 | 英文 | 解释 |
| --- | --- | --- |
| 人生设计 | Life Design | 把设计思维应用于人生与职业规划的方法论：先构建多个原型，再通过低成本实验验证，而非一次性做"正确的决定"。 |
| 工作观 | Workview | 你对"工作是为了什么"的根本看法：谋生、成就、创造、关系、意义……它是职业选择的地基。 |
| 人生观 | Lifeview | 你对"人为什么活着、什么算过得好"的根本看法。与工作观的一致性程度，往往决定职业选择的稳定性。 |
| 美好时光日志 | Good Time Journal | 记录日常活动中"投入度高 / 能量提升"与"心不在焉 / 能量消耗"的时刻，从中反推真实的兴趣与工作偏好。区别于"我觉得我喜欢什么"。 |
| 奥德赛计划 | Odyssey Plans | 同时设计三条（或更多）完全不同方向的未来五年路径：一条延续当前设想，一条若当前路径消失会做什么，一条不考虑金钱与面子的版本。目的是打破"唯一正确答案"的执念。 |
| 原型 / 原型验证 | Prototype | 用极低成本先试一小步（读一章书、看一节公开课、找一个人聊），来验证某个兴趣假设，而不是先做重大承诺。 |
| ★ 兴趣假设 | Interest Hypothesis | 万径对上述方法的改造核心：系统不告诉你"你是什么类型"，而是提出"你可能对 X 感兴趣"这样的**可证伪假设**，并给出验证方式。假设可以被推翻，标签不能。 |

## D. 技术术语

面向非技术读者的简版解释。详细设计见文档 05、06、07。

| 术语 | 英文 | 解释 |
| --- | --- | --- |
| 大语言模型 | LLM (Large Language Model) | 能理解与生成自然语言的模型。擅长理解意图、组织信息、生成解释；**不擅长精确计算与规则判断**，因此不能被用来算分数或校验招生章程。 |
| Agent（智能体） | Agent | 能自主调用工具、多步完成任务的 AI 程序。与"聊天机器人"的区别：它会规划步骤、查资料、自我检查。 |
| 多智能体 | Multi-Agent | 多个各有分工的 Agent 协作完成一件事，例如一个负责检索、一个负责生成、一个负责挑错。 |
| 技能 / 工具调用 | Agent Skills / Tool Calling | Agent 可以调用的外部能力，如"查数据库""执行规则校验""计算位次"。工具调用让模型能做事而不只是说话。 |
| 检索增强生成 | RAG (Retrieval-Augmented Generation) | 先检索真实资料，再让模型基于资料回答，并标注引用。是抑制"编造"的主要手段。 |
| 混合检索 | Hybrid Retrieval | 同时用关键词匹配、向量语义匹配、结构化条件过滤三种方式找资料，再合并排序。比单一方式更稳。 |
| 知识图谱 | Knowledge Graph (KG) | 用"实体—关系—实体"的方式组织知识。本项目有两个：**教育知识图谱（EKG）**描述高校、专业、课程、招生；**个人知识图谱（PKG）**描述你的兴趣、证据与假设。 |
| 确定性程序 / 规则引擎 | Deterministic Program / Rule Engine | 给定输入必然得到同一输出的代码。分数换算、选科校验、章程条件判断都必须走这里。 |
| 多目标优化 | Multi-objective Optimization | 在多个互相冲突的目标（如"专业匹配度""院校层次""地域""录取稳妥度"）之间寻找一组候选方案，而不是单一最优解。 |
| 可解释性 | Explainability | 系统能说清"为什么给出这个结论"。在万径里具体表现为：结论 + 依据 + 数据口径 + 可点开的原始来源。 |
| 幻觉 | Hallucination | 模型自信地生成不真实的内容。教育决策场景中，一条编造的录取规则就可能毁掉一个考生的机会，所以这是本项目的头号技术风险。 |
| 数据治理 | Data Governance | 对数据的采集、存储、使用、共享、删除全过程的规则与责任安排。 |
| 溯源 / 数据血缘 | Provenance / Lineage | 一条结论或一条数据从哪里来、经过了哪些处理。 |

## F. 容易混淆的三组概念

这三组是阅读时最容易理解偏差的地方，单独列出：

### F.1 学科（Discipline）vs 专业（Major）

- **学科**是知识的分类体系（数学、物理学、生物学、计算机科学与技术……），是研究和教学的领域划分。
- **专业**是高校的**培养单位**，是一个学生实际被录取、被培养、拿学位的身份。一个专业可能依托一个或多个学科；同一个学科在不同学校可能对应不同名称的专业。

**为什么重要：** 考生问的"这个专业学什么"是专业问题，而"这个领域在研究什么"是学科问题。混淆两者会导致推荐错位。本套文档严格区分，见文档 07 的实体建模。

### F.2 兴趣（Interest）vs 能力（Ability）vs 意愿（Willingness）

- **兴趣**：主动想接触、想了解（可通过长期行为观察）。
- **能力**：做得好、学得快（可通过成绩、项目、反馈观察）。
- **意愿**：愿意为此付出长期努力，包括忍受枯燥的部分。

三者常常不一致。一个人可能对物理有兴趣、能力中等、但不愿忍受数学推导的枯燥——这恰恰是最需要被区分的情况。详见文档 09 的 RQ2。

### F.3 推荐（Recommendation）vs 假设（Hypothesis）

- **推荐**：系统给出结论，用户执行或拒绝。
- **假设**：系统给出一个可能成立的方向 + 验证方式，用户去检验。

万径选择后者作为默认输出形态。这是产品哲学的核心差异，见文档 01 信念四。
