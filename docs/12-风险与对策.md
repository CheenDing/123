## 1. 风险管理方法

**问题：** 风险清单最常见的失败是写成「可能会有风险，我们会注意」——既没有触发信号，也没有责任角色，实际发生时无人认领。

**一句话结论：** 一条风险只有在满足三个条件时才算被管理：**有可观测的触发信号、有写死的应对动作、有明确的复查节奏**。三者缺一，就只是担忧。

### 1.1 可能性与影响的判定口径

| 等级 | 可能性 | 影响 |
| --- | --- | --- |
| 高 | 本项目周期内很可能发生 | 导致阶段门禁不通过，或引发合规/伦理事故 |
| 中 | 有可能发生，取决于执行 | 导致里程碑延期或指标不达标，但可补救 |
| 低 | 发生概率较小 | 局部返工，不影响方向判断 |

### 1.2 登记册结构说明

按文档 14 §3.4 的表格列数上限（不超过 6 列），登记册拆为两张表，编号一一对应：表 A 记录风险本体与责任归属，表 B 记录缓解动作与预警信号。

**复查节奏：** 每两周一次风险复盘，只讨论「触发信号是否出现」，不讨论抽象担忧；每次复盘更新可能性与影响评级 `[设计]`。

### 1.3 一处取舍：不做风险评分矩阵

常见做法是给每条风险打「可能性 × 影响」的分值并画热力图排序。我们放弃了它，原因是本项目处于早期阶段，既没有历史发生率，也没有可比的损失基数，任何分值都是假精度；一旦矩阵给出「R-T-01 得分 12，优先级最高」这样的结论，团队就会围着数字工作，而不是围着触发信号工作。

代价是失去了跨风险的可比排序，对外汇报时也不如热力图直观。我们改用「等级 + 触发信号 + 写死的应对动作」三件套：等级只用于粗分优先级，真正驱动行动的是信号是否亮灯。如果后续积累了足够的事件数据，可以再引入量化评分，但那时评分才有依据。

## 3. 风险登记册（表 B：缓解与预警）

| 编号 | 缓解措施 | 触发信号 | 早期预警指标 |
| --- | --- | --- | --- |
| R-P-01 | 提供「受控导入」作为替代路径（选段粘贴）；明示隐私边界与删除机制 | 招募阶段即出现大面积拒绝 | 导入意愿率 < 30% |
| R-P-02 | 措辞规范：只用「探索方向 / 假设」不用「你适合 / 你是」；每条附「证据不足」出口 | 访谈出现「被定义」表述 | 不适反馈 ≥ 1 人 / 10 人 |
| R-P-03 | 把画像绑定到具体任务（专业对比、探索清单），不做纯展示 | 首周后无后续操作 | 第 2 周留存 < 30% |
| R-T-01 | 引用强制回填、确定性规则引擎承担硬规则、抽样人工复核 | 抽查发现编造字段 | 无据陈述率 > 3% |
| R-T-02 | 分段解析 + 摘要压缩 + 异步处理；限制单次导入体量 | 单次导入耗时超预算 | P95 解析时长 > 60s |
| R-T-03 | 先支持 1–2 种主流格式；解析失败给出可操作的替代路径 | 失败集中在某一种格式 | 解析成功率 < 60% |
| R-D-01 | 设置参与门槛（仅成年或监护人陪同）；准备专项规则 | 招募触达未成年 | 未成年参与者占比 > 0 且无监护人流程 |
| R-D-02 | 用途白名单化；研究与改进分别单独同意；定期权限复核 | 内部申请跨用途取数 | 越权取数请求次数 > 0 |
| R-D-03 | 日志不记正文、追加写 + 哈希链、只读角色隔离 | 日志出现正文片段 | 日志含敏感字段命中 > 0 |
| R-O-01 | 建立双联系人；关键节点书面确认；准备不依赖该场景的备用验证方案 | 单方响应超一周 | 关键信息确认延迟 > 7 天 |
| R-O-02 | 把边界写进合作协议而非口头约定；提供不涉及画像的替代价值 | 对方要求开放画像筛选 | 出现「画像用于筛选」类需求 |
| R-O-03 | Phase 1 就启动数据谈判；先取公开数据作为兜底 | 数据提供方无明确答复 | 谈判周期 > 4 周无进展 |
| R-E-01 | 免费开放核心探索能力；不做焦虑营销；不承诺结果 | 宣传物料出现「抢先 / 落后」类表述 | 营销文案负面评审意见 > 0 |
| R-E-02 | 画像条目带有效期与复核机制；强制保留「多种可能」并列呈现 | 用户只记住单一标签 | 条目 90 天未复核占比 > 50% |
| R-S-01 | 关键模块双人可接手；文档先行；避免口头交接 | 单点角色连续缺席 | 关键模块仅有 1 人可维护 |
| R-S-02 | 数据接入与产品开发解耦；先用少量省份验证方法 | 接入进度落后计划两周 | 首批省份数据未按期到位 |
| R-S-03 | 研究设计先于开发完成；MVP 承担快速判断，正式研究承担证据 | 研究报告日期晚于门禁 | 研究结论未在 G1 前形成 |

## 4. 关键风险失效场景推演

每类挑 1–2 条最重要的做完整推演。推演的作用不是预言，而是**提前发现「我们以为的缓解措施其实不管用」**。

### 4.1 产品接受度：R-P-01 导入意愿崩塌

1. 招募 20 人，同意导入者 5 人（25%）。
2. 团队第一反应：「话术不好，改文案」。改完第二轮仍是 25%。
3. 访谈发现真实原因不是文案，而是**用户不愿意把自己和 AI 的私密对话交给一个陌生团队**，且不相信「30 天后删除」的承诺。
4. 若团队继续加码说服（送礼品、延长试用），会得到一批「为了礼品而导入」的样本，实验数据被污染，H-M1 的结论变成假阳性。
5. **正确应对：** 承认入口形态有问题，切换到「受控导入」（用户自己挑 3–5 段粘贴）或纯结构化自陈，并明确记录「批量导入假设被证伪」。
6. **教训：** 缓解措施若只是「让用户更愿意」，而不是「降低用户承担的风险」，就不是真缓解。

### 4.2 技术幻觉：R-T-01 编造选科要求

1. Agent 回答「这个专业要求物理和化学必选」，但实际该省该年只要求物理。
2. 用户据此排除了一个本可报考的方向。
3. 这类错误不会引发投诉（用户不知道自己错了），但直接损害决策质量，也是最难被发现的错误类型。
4. **缓解的关键不是「让模型更准」，而是让硬规则不经过模型**：选科要求、批次、体检限制一律由确定性规则引擎判定，模型只负责解释规则结果。
5. 残余风险：规则库本身不全或过期。因此必须有「规则未覆盖」的显式拒答，而不是让模型自行补全。
6. **教训：** 幻觉治理的主战场在架构分工，不在提示词。

### 4.3 数据合规：R-D-02 二次利用越界

1. 研究组为了做 RQ2，直接从画像库拉取全部用户数据，理由是「反正都同意了」。
2. 但用户同意的是「生成画像」，不是「用于研究」。
3. 这类越界在内部往往不被视为事故，因为「没有对外泄露」。但它恰恰是监管与伦理审查最关注的问题。
4. **缓解：** 用途白名单 + 研究数据独立申请 + 去标识化数据集 + 定期权限复核；技术上禁止研究环境直连生产画像库。
5. **教训：** 合规事故多数不是黑客造成的，是内部「顺手用一下」造成的。技术隔离比制度约束可靠。

### 4.4 合作组织：R-O-02 高校要求画像筛选

1. 试点方提出：「能不能帮我们从考生里筛出对某专业真有兴趣的，我们做重点触达。」
2. 这个需求对高校很有价值，且技术上完全可行。
3. 一旦同意，产品性质立即从「帮考生认识自己」变为「帮高校筛人」，文档 08 §6 的三道门全部失效。
4. **缓解：** 在合作协议阶段就把用途黑名单写死；准备替代价值（如「专业探索活动的报名入口」，由考生自愿报名而非系统筛选）。
5. **残余风险：** 合作关系紧张时，这条边界会被反复试探。需要有明确的对外话术与拒绝预案。
6. **教训：** 伦理边界不是写在文档里就守得住的，必须在商务条款里，因为那才是真正被执行的地方。

### 4.5 伦理社会：R-E-02 画像固化

1. 系统告诉考生「你的证据显示对人文社科方向的持续兴趣较强」。
2. 考生理解为「我不适合理科」，于是放弃了一个本来可以尝试的方向。
3. 问题不在于结论错，而在于**结论的呈现方式把概率性判断变成了身份判定**。
4. **缓解：** 强制并列呈现（列出证据不足的替代方向）；每条结论带有效期与复核入口；措辞统一用「探索方向」而非「你的特质」；在关键节点（如选科、填志愿前）主动提示「画像只是参考之一」。
5. **残余风险：** 无论怎么措辞，用户仍可能只记住标签。这是无法完全消除的，只能通过界面设计与文案持续对抗。
6. **教训：** 这是本文列出的「不可完全缓解」风险之一，应对立场见 §5。

### 4.6 进度资源：R-S-02 数据接入拖垮 Phase 3

1. Phase 3 需要多省招生数据，谈判在第 2 周启动，第 8 周仍无结论。
2. 工程团队无事可做，或被迫用非授权渠道获取数据（严重合规风险）。
3. **缓解：** 数据接入与产品开发解耦，先用 1 个省的公开数据把方法与规则引擎做完；非授权数据一律禁止，哪怕只是「先试试」。
4. **教训：** 数据依赖必须前置到 Phase 1，且必须准备「只有公开数据也能验证方法」的兜底路径。

## 5. 不可完全缓解的风险与项目立场

有些风险无法通过措施消除，只能选择立场。写清楚立场，比假装能解决更诚实 `[已确定]`。

| 风险 | 为什么不可完全缓解 | 项目立场 |
| --- | --- | --- |
| LLM 幻觉 | 生成式模型的输出无法保证零错误 | 把硬规则移出模型；接受「解释层可能出错」，并通过引用回填与拒答降低影响；绝不承诺零错误 |
| 兴趣测量的效度 | 教育心理学无公认金标准 | 多方法三角验证；结论表述为假设；承认测量不确定性，不宣称「测出真实兴趣」 |
| 画像标签化 | 任何标签都可能被用户简化为身份 | 持续用产品设计与文案对抗；承认残余影响；不做「性格类型」类强标签 |
| 招生政策年际变化 | 外部政策不可控 | 只做规则执行与信息组织，不做趋势预测；数据按年度失效 |
| 用户隐私顾虑 | 无法通过技术完全消除 | 提供不导入也能用的路径；把控制权（撤回/删除）做成一等功能而非合规摆设 |

**一条边界立场：** 如果未来某天，产品的商业压力要求突破文档 08 §6 的高校边界（例如把画像用于招生筛选），那么正确的选择是**放弃该商业机会**，而不是修改边界文档。这条立场写入项目章程级别的约定。

## 6. 早期预警指标体系

预警指标要能在事故之前亮灯，且必须可自动采集或低成本采集。

| 指标 | 阈值（`[假设]`） | 监测频率 | 超阈值动作 |
| --- | --- | --- | --- |
| 导入意愿率 | < 30% | 每次招募 | 启动 R-P-01 预案 |
| 无据陈述率（抽样） | > 3% | 每周 | 冻结相关回答模板，追加人工复核 |
| 越界表述命中（录取保证 / 心理诊断） | > 0 | 实时 + 每日汇总 | 立即下线相关输出，复盘提示词与规则 |
| 越权取数请求 | > 0 | 每周 | 权限复核，通报 |
| 不适反馈人数 | ≥ 1 人 / 10 人 | 每次访谈 | 暂停招募，重审措辞与呈现 |
| 合作伙伴「画像筛选」类需求 | > 0 | 每次沟通 | 启动 §4.4 拒绝预案并上报 |
| 关键模块单人可维护 | 存在 | 每月 | 补文档与结对 |
| 数据接入延期 | > 2 周 | 每两周 | 启动兜底路径（仅公开数据） |
