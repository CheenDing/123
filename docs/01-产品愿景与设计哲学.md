## 1. 我们要回答的那个问题

### 1.1 一个具体的场景

一个十八岁的人，拿到高考成绩，坐在电脑前，要在几天之内填完一张志愿表。

他手里有什么？一本招生计划、一堆院校简介、若干年的录取位次、以及一个"冲稳保"推荐列表。信息很充分。但真正卡住他的问题不是信息不足，而是：

> 我到底想学什么？

这个问题在那一刻是**无解的**。因为他从来没有被要求认真想过它，也没有任何工具帮他想过。整个高中阶段，他被训练的是"如何把分数考高"；到了要选专业的那一刻，系统却假设他已经知道自己要什么，只差一个匹配算法。

于是最常见的结果是三种：按分数选（不浪费一分）、按名字选（听起来体面）、按家长选（就业稳定）。三种都不是"按自己选"。

### 1.2 我们判断这是一个结构性的错位

| 环节 | 现有系统假设 | 真实情况 |
| --- | --- | --- |
| 决策起点 | 分数已知，目标明确 | 分数已知，目标未知 |
| 决策依据 | 院校/专业的外部属性（排名、分数、就业率） | 决策者自身的兴趣、能力、价值观尚未成形 |
| 决策时间 | 集中在出分后的数天 | 需要以月甚至年为单位的探索 |
| 决策主体 | 考生本人 | 考生 + 家长 + 老师，意见经常冲突且缺乏共同语言 |
| 决策质量评估 | 是否被录取、是否浪费分数 | 四年后是否还认同这个选择 |

现有平台把"志愿填报"当成一个**约束满足问题**：给定分数、省份、选科，输出一个录取概率最优的序列。这个问题定义是自洽的，但它优化的是"不浪费分数"，而不是"不浪费四年"。

### 1.3 所以问题应该被重新表述

不是"根据分数选择大学"，而是：

> **如何帮助一个尚未真正认识自己的年轻人，通过有据可依的探索，形成自己的教育目标，并在此基础上做出一个他愿意为之负责的选择？**

万径要做的，是这句话里的三个动作：**认识自己 → 探索专业 → 选择大学**。顺序不能颠倒，也不能跳过第一步直接给推荐。

## 2. 为什么是现在

### 2.1 供给端：AI 第一次有能力"陪伴式地理解一个人"

[已确定] 三个能力变化同时发生：

1. **长上下文与长期记忆**。可以在跨越数月的对话中保持对一个人的连续理解，而不是每次重置。
2. **多轮追问与结构化抽取**。可以从自然语言里抽出"关注的主题""提问的复杂度""反复出现的困惑"，而不依赖用户填问卷。
3. **检索增强与工具调用**。可以让模型在回答专业问题时引用真实培养方案，而不是凭印象编造。

前两点让"长期交互式自我探索"从概念变成可以尝试的工程问题；第三点让"可信"成为可能——但只是可能，需要严格的工程约束（见文档 05、06）。

### 2.2 需求端：新高考把"探索"提前了

[已确定] 新高考的选科制度（如"3+1+2"）要求考生在高二甚至高一就确定选考科目，而选科直接决定了可报考的专业范围。这意味着：

- 专业方向的决策点被**前置**到了自我认知最不成熟的阶段。
- 选科错了，后面分数再高也补不回来（很多专业有硬性选科要求）。
- 但社会供给的探索工具几乎没有——学校有生涯规划课，通常是一学期几节课加一次测评。

这是一个**结构性缺口**：决策被提前，认知支持没有跟上。

### 2.3 技术现实：我们不认为 LLM 可以直接"给建议"

[已确定] 一个诚实的判断：把"你适合学计算机"这句话交给 LLM 直接生成，是错误的做法。理由有三：

- 模型对具体的人没有足够信息，只能靠话术制造"被理解"的错觉；
- 模型对高校专业的具体培养要求掌握不准确，容易编造课程与就业信息；
- 一旦输出被当成权威建议，责任无法界定，用户也无法反驳。

因此万径的设计原则从一开始就是：**LLM 负责理解与解释，确定性程序负责规则与计算，画像的每个判断必须挂在证据上**。这条原则贯穿全部技术文档。

## 3. 我们的回答：一条有顺序的路径

```text
   ┌─────────────────────────────────────────────────────────┐
   │  阶段一：认识自己                                        │
   │  长期交互记忆 → 个人画像（带证据、时间、置信度）          │
   │  人生设计对话：Workview / Lifeview / Good Time Journal    │
   │  产出：可验证的兴趣假设，而不是人格标签                    │
   └──────────────────────────┬──────────────────────────────┘
                              │  画像作为输入，用户可控可见
                              v
   ┌─────────────────────────────────────────────────────────┐
   │  阶段二：探索专业                                        │
   │  兴趣主题 ↔ 学科知识 ↔ 专业培养要求 的映射                │
   │  多专业对比、课程体系解读、能力要求说明                   │
   │  产出：若干条候选探索路径 + 现实可执行的验证任务           │
   └──────────────────────────┬──────────────────────────────┘
                              │  收敛到有限的候选集合
                              v
   ┌─────────────────────────────────────────────────────────┐
   │  阶段三：选择大学                                        │
   │  位次与录取数据分析（确定性计算）                         │
   │  选科要求 / 招生章程 / 专业组 校验（确定性规则）          │
   │  多目标组合优化 → 冲稳保方案 + 每条建议的理由             │
   │  产出：可解释、可复核的志愿方案                           │
   └─────────────────────────────────────────────────────────┘
```

**关键点：这不是三个功能，而是一条有依赖关系的路径。** 阶段二的输入是阶段一的产出，阶段三的候选集来自阶段二的收敛。如果用户跳过阶段一直接要推荐，系统仍能工作（降级为传统填报工具），但必须明确告知：此时的推荐只基于分数，不基于对你这个人的理解。

这个"降级但不欺骗"的设计，是我们对产品诚实性的最低要求。

## 4. 三条基本原则的展开

### 4.1 Understand the Person：理解一个人，而不仅仅是分析他的成绩

**我们做的：**

- [设计中] 在用户明确授权下，导入其与 ChatGPT / Claude / DeepSeek 等平台的历史对话，作为长期交互记忆的原料。
- [设计中] 结合日记、学习记录、主动访谈，形成持续更新的个人画像。
- [设计中] 画像中的每一项判断，都必须能回溯到原始证据片段、时间戳与置信度。
- [已确定] 用户对画像拥有完整主权：可查看、可纠正、可删除、可导出。

**我们刻意不做的：**

- 不做人格测评打分（MBTI、霍兰德之类的简化标签）。理由：这类工具给出的是**归类**，而我们需要的是**可证伪的假设**。给一个十八岁的人贴上"你是 INTP 型"的标签，会关闭他的探索空间，而不是打开它。
- 不从对话里推断心理健康状况。这不是我们的能力边界之内的事，越界是不负责任的。

### 4.2 Explore the Possibilities：帮助探索，而不是过早收敛

**我们做的：**

- [设计中] 一次给出多条候选路径（对应 Odyssey Plans 的多版本人生设计），而不是单一推荐。
- [设计中] 解释"这个专业具体学什么、需要什么能力、投入多少"，而不只是"这个专业好不好"。
- [设计中] 把抽象兴趣转化为**现实可执行的验证任务**——例如"去读一本《经济学原理》的前三章，如果一周内你主动想读第四章，这个兴趣值得继续"。

**我们刻意不做的：**

- 不提供"最适合你的专业 Top 3"这种排行榜式输出作为终点。排行榜是探索的**起点**，不是结论。
- 不用"热门专业""就业前景好"作为主要排序依据。这类信息是真实的，但它回答的是社会平均问题，不是这个人的问题。

### 4.3 Make Informed Decisions：让选择建立在可核查的基础上

**我们做的：**

- [已确定] 志愿决策环节的所有数据计算与规则校验，由确定性程序完成，不由 LLM 生成。
- [已确定] 每一条建议都必须能回答"依据是什么"：哪年的数据、哪个省份、什么口径、适用哪条招生章程条款。
- [设计中] 多目标约束优化：在分数约束、选科约束、地域偏好、专业偏好、家庭期望之间寻找候选方案集，并展示每条方案的取舍。

**我们刻意不做的：**

- 不做录取概率的精确承诺。我们给的是基于历史位次的**风险区间**与**判断依据**，不是"录取概率 87%"这种伪精确数字。
- 不替用户做最终决定。系统输出的是"如果你重视 A，选 X；如果重视 B，选 Y"，决定权始终在用户。

## 5. 两个产品方向，一个知识底座

```text
                    万径 WANJING
        Personalized Education Intelligence
                        │
        ┌───────────────┴───────────────┐
        │                               │
  考生端（C）                      高校端（B）
  Personal Education Discovery     University Intelligence
        │                               │
  · 长期交互记忆与个人画像          · 高校专业知识库
  · 人生设计与自我探索              · 官方招生 Agent
  · 专业发现与匹配                  · 个性化专业探索
  · 智能志愿决策                    · 招生部门管理后台
        │                               │
        └───────────────┬───────────────┘
                        │
              共享：教育知识图谱 + 决策引擎 + 数据治理
                        │
              可信数据层：招生计划 / 专业 / 培养方案
                        高校 / 科研 / 升学就业
```

**为什么两边都要做？**

单做考生端，最大的瓶颈是数据：拿不到高校权威的专业培养信息，专业解读就只能靠模型编。单做高校端，最大的瓶颈是动机：招生办没有动力把内容结构化，因为结构化之后也没人用。

两边一起做，形成一个正循环：高校侧提供**权威内容**，考生侧产生**真实需求信号**（哪些专业被反复咨询、哪些信息考生看不懂），这些信号反过来告诉高校该补什么内容。这是我们判断这个项目能持续运转的核心机制，也是它区别于"又一个志愿填报 App"的地方。

**风险也要说清楚：** 双边平台最常见的失败是两边都没做透。因此在路线图上我们不做平行推进，而是 Phase 1 先做透考生侧（文档 10 有阶段门禁）。

## 6. 设计哲学：六条我们愿意被检验的信念

### 信念一：AI 不应该替一个年轻人决定他应该成为谁

它应该帮助他认识自己的兴趣，理解世界的知识体系，探索不同的可能性，并拥有做出自主选择的能力。

**这条如何落到工程上：** 系统的每一次输出，都必须留下用户"不同意"的入口。画像可以被否认为错误，推荐可以被标记为"这不像我"。如果一个设计让用户只能接受、无法反驳，它就违背了这条信念。

### 信念二：可解释比准确更重要，至少在早期是这样

一个说不清理由的正确推荐，和一个说得清理由的不完美推荐，后者对用户的长期价值更高——因为它教会了用户如何判断，而不只是给出答案。

**代价：** 可解释性会显著增加工程复杂度（引用回填、规则溯源、证据链存储）。我们接受这个代价，把它当成产品的核心成本项而不是附加项。

### 信念三：证据链是产品的一部分，不是后台实现细节

用户应该能点开"我们认为你对生物感兴趣"这句话，看到它是从哪三次对话、哪几篇日记里得出的，各自置信度多少。

**这条的隐含要求：** 数据模型从第一天就要为证据留位置。事后补证据链，基本等于重做（见文档 07）。

### 信念四：不贴标签，提假设

"你可能对'用计算方法理解生命现象'这件事感兴趣"——这是假设，可以被验证、被推翻。

"你是一个理科型人格"——这是标签，只能被接受或反抗。

我们选择前者。因为假设会引导行动，标签只会终止思考。

### 信念五：确定性的事交给代码，判断的事才交给模型

分数换算、位次比较、选科要求匹配、招生章程条件校验、冲稳保组合——这些有唯一正确答案，必须由代码算，且必须可复现。

理解意图、组织信息、解释取舍、追问澄清——这些没有唯一答案，才交给 LLM。

**这条是可信任性的地基。** 一旦让 LLM 参与它不擅长的确定性计算，整个系统的可信度就崩了，而且是那种"偶尔对、偶尔错、用户无法分辨"的崩塌，最危险。

### 信念六：对大学而言，招生不该止于展示分数线

大学应该能够真正向每一位考生解释：我们在研究什么、培养什么样的人、这里的哪些知识和机会可能与你的未来产生联系。

这句话也是我们对合作高校的价值主张：**不是帮你把招生页面做得更漂亮，而是帮你把"我们培养什么人"这件事讲清楚，并且讲给对的人听。**

## 7. 我们不做什么（负面清单）

一份诚实的产品说明必须包含边界。以下是我们明确不做的事：

| 不做什么 | 原因 |
| --- | --- |
| 不做录取结果的保证或承诺 | 录取受当年计划、报考人数、政策影响，任何承诺都是不负责的 |
| 不做心理诊断、人格障碍识别、心理健康评估 | 超出能力与资质边界，且对未成年人风险极高 |
| 不做"代填志愿"的一键托管 | 决策权必须留在用户手里，这是产品的伦理底线 |
| 不做院校/专业的商业排名或付费推荐位 | 一旦推荐位可购买，全部推荐的可信度归零 |
| 不用考生画像做录取相关的任何自动决策 | 画像只用于"帮他探索"，绝不用于"评判他"（详见文档 08） |
| 不在未授权情况下采集或推断用户信息 | 包括但不限于：不导入未经授权的对话记录、不爬取社交内容 |
| 不做留学/艺考/强基等细分赛道的全覆盖 | Phase 1–4 只聚焦普通高考统招，其余场景明确排除 |

## 8. 怎么判断这件事成不成立

我们不想用"用户数""日活"这类指标自我安慰。以下是我们认为真正能证伪这个项目的判据（与文档 09、11 呼应）：

1. **画像有效性**：从长期交互中提取的兴趣判断，能否被用户本人认可（"这确实是我，而且我自己之前没这么清楚地表达过"），且这种认可率显著高于随机生成的画像描述（即排除巴纳姆效应）。
2. **探索行为改变**：使用产品后，用户是否真的去做了此前不会做的探索行为（读书、看公开课、找学长聊、做小项目），而不是只多看了几个页面。
3. **决策质量**：用户最终方案的**理由**是否从"分数刚好""家长说好"转变为能说出与自己兴趣/能力的具体关联。
4. **高校侧可用性**：招生办是否愿意持续维护知识库——如果内容维护成本高于其感知价值，B 端模式不成立。
5. **可信度**：在专业信息问答上，事实性错误率能否压到一个可接受阈值以下（具体阈值见文档 06 的评测方案）。

**如果第 1 条不成立，整个"理解一个人"的前提就崩了，项目应当转向或停止。** 这是我们给自己设的否决线。

## 9. 与现有方案的关系

我们不认为万径是现有志愿填报工具的替代品。更准确的位置是：

```text
   现有工具覆盖的区间              万径要补的区间
   ┌──────────────────┐    ┌──────────────────────────┐
   │  出分后的匹配计算  │ ←  │  出分前的自我探索与专业发现 │
   │  冲稳保推荐       │    │  出分后的可解释决策支持     │
   └──────────────────┘    └──────────────────────────┘
              ↑                        ↑
         「不浪费分数」            「不浪费四年」
```

理想状态下，用户在出分前几个月就开始使用万径完成探索，出分后把已经收敛的候选集带进决策环节。如果用户出分后才来，我们仍然能提供决策支持，只是会明确告知：这份方案缺少"对人的理解"这一层输入。

---

## 10. 一句话总结

万径想做的事，说到底是一句话：

> **把"选专业"从一次基于分数的匹配计算，还原成一个年轻人认识自己、认识世界、并为自己做决定的过程——然后给这个过程提供工具、证据和诚实的边界。**

万径纵横，智见未来。

| RQ1 | **长期交互与个人理解**：能否通过人与 AI 的长期交互记录，发现传统兴趣问卷难以识别的持续兴趣与学习动机？ |
| RQ2 | **兴趣发现与验证**：如何区分短期兴趣、长期兴趣、能力倾向与真实学习意愿？ |
| RQ3 | **个人画像与专业匹配**：如何建立可解释、可验证的个人特征与专业培养要求之间的映射？ |
| RQ4 | **Agent 决策可靠性**：如何通过检索增强、确定性规则和多 Agent 审核，减少招生信息幻觉与错误推荐？ |
| RQ5 | **个性化招生服务**：如何将高校专业知识转化为能够理解不同考生需求的智能交互服务？ |

> 注意区分：本节是**研究问题**（需要被回答、可能被证否）；本文第 8 节是**成功判据**（回答之后用来判定的标准）。两者一一对应但不相同，映射关系见文档 09 §2.1。

### 11.2 四阶段主题（Phase 1–4）

| 阶段 | 主题 | 范围要点 | 状态 |
| --- | --- | --- | --- |
| Phase 1 | **Personal Discovery MVP** | 历史 AI 对话记录导入、长期交互兴趣提取、基于证据的个人画像、苏格拉底式人生探索 Agent、多种未来发展路径生成 | `[规划]` |
| Phase 2 | **Major Discovery** | 学科与专业知识库、专业培养方案结构化、个人兴趣与专业匹配、专业探索报告、现实探索任务与反馈机制 | `[规划]` |
| Phase 3 | **Admission Decision** | 多省份招生数据接入、历年录取数据分析、志愿规则引擎、冲稳保推荐、多目标志愿组合优化 | `[规划]` |
| Phase 4 | **University Intelligence** | 东北大学专业知识库、东北大学招生 Agent、个性化专业探索、高校招生部门管理平台、多高校知识库接入 | `[规划]` |

**两条约束：**

1. 阶段之间**串行为主**。我们不做考生端与高校端的平行推进——双边平台最常见的失败是两边都没做透（见本文 §5）。
2. 「规模化与效果验证」不单列为阶段，它是贯穿 Phase 2–4 的**横切目标**，并在每个阶段的门禁里被检查。
