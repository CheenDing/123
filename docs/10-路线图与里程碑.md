## 1. 路线图的组织原则

**问题：** 早期项目最容易犯的错是把路线图写成模块交付清单——「先做记忆，再做探索，再做决策」。这会导致每个阶段都「完成了」，但没有一个阶段真正回答了「这条路成不成立」。

**一句话结论：** 每个阶段只回答一个可证伪的问题，阶段门禁（gate）不看「功能做完了没有」，只看「这个问题的答案是否支持继续投入」。功能是阶段的手段，不是阶段的成果。

四条原则 `[已确定]`：

1. **一阶段一问**：每阶段设定一个主问题，其余工作都是为该问题提供条件。
2. **证据链优先于覆盖广度**：任何阶段都可以砍掉若干省份、若干高校、若干功能，但不得砍掉「证据可溯 + 授权可撤回 + 审计可查」。
3. **门禁前置声明**：进入下一阶段的条件在阶段开始前写死，不允许事后调整口径。
4. **降级有预案**：资源不足时按预先排好的顺序砍，而不是临时慌乱决策。

> **取舍：** 我们放弃了「考生端与高校端同时做出可演示版本」的常规做法。代价是 Phase 1–3 对外几乎没有 B 端可展示物，融资与宣讲会吃亏；收益是避免了在高校侧合作尚未落定时提前投入，也避免了在未验证的核心假设上叠加多层功能，导致后面无法判断到底是哪一层错了。

## 2. 四阶段总览

阶段主题与 [README](../README.md) 的「路线图概览」及文档 01 保持一致，采用「英文主题名 + 中文副标题」的写法，以便与 README、01 逐字对照。

| 阶段 | 主题 | 主问题 | 关键产出 | 大致时间盒 |
| --- | --- | --- | --- | --- |
| Phase 1 | Personal Discovery MVP（个人发现 MVP） | 从历史对话提取的画像，能否被考生认可、并支撑他自己说出多条未来路径 | 可纠正画像 + 探索 Agent + 路径生成 + MVP 报告 | `[假设]` 8–10 周 |
| Phase 2 | Major Discovery（专业发现） | 兴趣能否被映射到专业培养要求上，且映射可被核查 | 专业知识库 + 可解释匹配 + 探索报告 | `[假设]` 10–12 周 |
| Phase 3 | Admission Decision（志愿决策） | 决策建议是否每一条约束都可回指规则与数据 | 规则引擎 + 冲稳保推荐 + 组合优化 | `[假设]` 12–16 周 |
| Phase 4 | University Intelligence（高校智能） | 高校侧是否获得真实工作流价值，治理能否支撑多校 | 东北大学知识库 + 招生 Agent + 管理平台 + 外部审计 | `[假设]` 试点 12 周起，持续 |

四个阶段之上有三条**横切主线**，不属于任何单一阶段，也不单列成阶段 `[已确定]`：

- **数据治理与证据链**（文档 08）：从 Phase 1 第一天起生效，越往后越重。
- **研究评估**（文档 09）：RQ1–RQ2 在 Phase 1–2，RQ3 在 Phase 2，RQ4 在 Phase 3，RQ5 在 Phase 4。
- **规模化与效果验证**：按文档 01 §11.2 的约束，它是贯穿 Phase 2–4 的横切目标，在每个阶段的门禁里被检查（规模相关项见 G2/G3，效果收口见 G4）；多省扩张落在 Phase 3，多校扩张落在 Phase 4。

## 3. Phase 1：Personal Discovery MVP（个人发现 MVP）

**目标：** 验证「导入第三方 AI 对话 → 长期交互提取兴趣 → 证据化个人画像 → 苏格拉底式探索引导 → 多条未来发展路径」这条链路成立。判据不是「功能能跑」，而是：考生认这个画像，并且能自己说出不止一条可能的方向。

**范围：** 对话导入与解析、兴趣片段抽取、画像条目与置信度分档、画像查看 / 纠正 / 删除、苏格拉底式人生探索 Agent（工作观与人生观、美好时光日志）、多条未来发展路径生成（奥德赛计划式，≥ 3 条并列）。

**不做什么：** 不做专业知识库与专业匹配，不做志愿方案与录取计算，不做多省数据接入，不做任何高校侧功能，不做商业化功能。

**交付物：** 可运行 MVP、对话解析覆盖率报告、画像证据链界面、探索对话实录与引导性评测、路径生成样例（去标识化）、MVP 实验报告（见 [MVP 实验与验收标准](11-MVP实验与验收标准.md)）、授权与伦理流程落地记录。

**验收标准：** 满足 G1 全部条件。

**依赖：** 授权与删除流程（文档 08）先于一切功能开发；对话策略（文档 06 的苏格拉底式设计）与 RQ1 / RQ2 的研究设计（文档 09）先于 Agent 定稿。

**风险：** 用户不愿导入对话；解析质量不足导致画像空洞；探索 Agent 滑向引导性提问（把「启发」做成「暗示」）；路径生成退化为模板填空。

| 里程碑 | 交付物 | 判定条件 |
| --- | --- | --- |
| M1.1 | 授权与数据生命周期最小实现 | 导入 / 撤回 / 导出 / 删除四条路径可端到端跑通 |
| M1.2 | 对话导入解析与兴趣片段抽取 | 目标格式可解析率 ≥ 60% `[假设]`；抽取片段人工核对准确率 ≥ 80% `[假设]` |
| M1.3 | 证据化个人画像 | 条目 100% 挂证据；任一条目可在 30 秒内定位原文；纠正后级联失效无残留 |
| M1.4 | 苏格拉底式人生探索 Agent | 抽样 20 段对话，引导性提问占比 ≤ 10% `[假设]`；每轮产出 0–3 条待确认条目，或明确「本轮无产出」 |
| M1.5 | 多条未来发展路径生成 | 每位考生 ≥ 3 条可区分路径，每条附依据与不确定性；不出现单一「最适合」结论 |
| M1.6 | MVP 实验与报告 | 达到文档 11 的 go 判据 |

## 4. Phase 2：Major Discovery（专业发现）

**目标：** 验证「可解释的兴趣—专业映射」站不站得住：考生能否顺着证据链理解「为什么这个专业值得了解」，而不只是又看了一遍专业介绍页。

**范围：** 学科与专业知识库（教育知识图谱首批实体）、培养方案结构化、兴趣与专业的可解释匹配、专业探索报告、现实探索任务与反馈机制（读一本书、看一门公开课、做一个小项目、找学长聊一次），以及探索结果回流为画像证据。

**不做什么：** 不做录取数据与志愿规则；不做高校侧招生 Agent；不做多省覆盖；不做专业之间的横向比较与打分。

**交付物：** 专业知识库 v1 与培养方案结构化 schema、映射与解释的可核查性报告、专业探索报告样例、探索任务完成率数据、RQ3 初步结果。

**验收标准：** 满足 G2。

**依赖：** Phase 1 的画像可用；教育知识图谱建模（文档 07）先于知识库建设；资料获取（优先使用公开培养方案，其次试点方提供）。

**风险：** 字段不全导致解释编造；映射层「主题 → 学科知识点」是最不可靠的一段（文档 07 已标注）；探索任务沦为打卡清单，反馈无法回流。

| 里程碑 | 交付物 | 判定条件 |
| --- | --- | --- |
| M2.1 | 学科与专业知识库 v1 | 专业实体字段完整率 ≥ 80% `[假设]`，每字段标注来源等级 |
| M2.2 | 培养方案结构化 | 培养目标 / 核心课程 / 能力要求三字段可被解释引用，抽样编造率 = 0 |
| M2.3 | 兴趣—专业可解释匹配 | 每条匹配理由可回指「画像条目 → 学科知识点 → 课程」完整链条 |
| M2.4 | 专业探索报告 | 报告须含依据、不确定性、替代方向三部分，缺一不算通过 |
| M2.5 | 现实探索任务与反馈机制 | 任务完成率 ≥ 30% `[假设]`；完成后的反馈能作为新证据或负证据写回画像 |
| M2.6 | RQ3 初步结果 | 用户认可度与专家一致性达到文档 09 §5 的阈值 |

## 5. Phase 3：Admission Decision（志愿决策）

**目标：** 验证决策建议的可靠性：每一条约束都能回指规则或数据来源，且绝不出现「录取保证」类表述。

**范围：** 多省份招生数据接入（首批目标省份）、历年录取分析（以位次为口径，含年际变化提示）、志愿规则引擎（选科、批次、体检等硬规则）、冲（Reach）稳（Match）保（Safety）推荐、多目标组合优化。

**不做什么：** 不做录取概率的百分比承诺；不做代填志愿；不做付费推荐位；不做高校侧功能；不做跨校比较评价。

**交付物：** 数据接入清单（省份 / 年份 / 科类 / 批次 / 来源五项齐全）、规则引擎与校验报告、历年录取分析口径说明、冲稳保方案样例、组合优化的目标与权重说明、RQ4 结果。

**验收标准：** 满足 G3。

**依赖：** Phase 2 收敛出的专业候选集；数据获取的合法性与完整性（文档 08 §9）。数据接入谈判应在 Phase 1 就启动，不要等本阶段。

**风险：** 数据口径不一致；幻觉进入硬规则（后果最严重）；多目标优化的权重缺乏实证依据，可能得到「精确的错误」。

| 里程碑 | 交付物 | 判定条件 |
| --- | --- | --- |
| M3.1 | 多省招生数据接入（首批） | 每省数据五项齐全；跨年数据只展示、不参与计算 |
| M3.2 | 历年录取分析 | 每条位次口径标注年份与科类；明确提示年际波动，不做趋势预测 |
| M3.3 | 志愿规则引擎 | 硬规则可判定项覆盖率 ≥ 90% `[假设]`，规则单元测试全覆盖 |
| M3.4 | 冲稳保推荐 | 方案中每条约束可回指规则或数据来源；不输出概率百分数 |
| M3.5 | 多目标组合优化 | 目标函数与权重全部显式列出、用户可见，无隐式偏好 |
| M3.6 | 可靠性评估 | RQ4 指标全部达标，越界率 = 0 |

## 6. Phase 4：University Intelligence（高校智能）

**目标：** 验证高校侧是否获得真实工作流价值，以及治理与质量体系能否支撑多校接入——不是验证「能不能再多接几个学校」。

**范围：** 东北大学专业知识库、东北大学招生 Agent、个性化专业探索（仅在考生当次主动授权下使用画像摘要，按文档 08 §6 三道门执行）、高校招生部门管理平台（内容维护、知识库校验、咨询分析）、多高校知识库接入；末段完成效果验证与外部审计。

**不做什么：** 不用画像做任何录取相关决策；不做定向营销与招生触达；不做数据出境；不做超出教育决策场景的画像应用；不做跨校比较评价。

**交付物：** 试点专业知识库、招生 Agent 试点记录、管理平台最小版、多校接入手册与治理流程、效果评估报告（只含方法与可验证指标）、外部审计意见。

**验收标准：** 满足 G4。

**依赖：** Phase 1–3 门禁全部通过；东北大学试点场景的合作推进（这是全程最大的外部依赖，见文档 12 R-O-01）；文档 01 §7 的负面清单作为需求边界。

**风险：** 单点联系人导致停摆；对方提出「用画像筛选考生」的需求压力；内容维护成本高于感知价值；规模化稀释质量。

| 里程碑 | 交付物 | 判定条件 |
| --- | --- | --- |
| M4.1 | 东北大学专业知识库 | 字段完整率与来源标注达标；校方书面确认内容可用 |
| M4.2 | 东北大学招生 Agent | 重复性问题答复工时可测量下降 `[假设]`；拒答策略覆盖应拒答问题 |
| M4.3 | 个性化专业探索（授权版） | 画像摘要仅在考生当次授权下可见；越界访问 = 0 |
| M4.4 | 招生部门管理平台 | 内容维护与校验流程可在无工程师介入下完成 |
| M4.5 | 多高校知识库接入 | 新校接入 ≤ 4 周 `[假设]` 且通过字段完整率检查 |
| M4.6 | 效果验证与外部审计 | 审计结论无高风险未整改项；年度更新机制完整运行一个周期 |

## 7. 阶段门禁

门禁条件是**否决式**的：全部满足才可进入下一阶段，不设「部分满足」 `[设计中]`。

| 门禁 | 条件（全部满足） | 不满足时 |
| --- | --- | --- |
| G1 → Phase 2 | ① 授权 / 撤回 / 导出 / 删除四路径可用；② MVP 达到文档 11 的 go 判据；③ RQ1 / RQ2 至少一条假设得到支持；④ 无重大伦理投诉 | 回到 MVP 迭代，不进入 Phase 2；连续两轮未过触发 pivot 评估 |
| G2 → Phase 3 | ① 知识库字段完整率达标且来源标注齐全；② 映射解释编造率 = 0；③ 探索报告三要素齐全；④ 现实探索任务完成率达标；⑤ RQ3 达到初步阈值 | 缩减范围（只做目标专业），不扩展省份 |
| G3 → Phase 4 | ① 规则覆盖率与单测达标；② RQ4 全部指标达标、越界率 = 0；③ 多省数据五项齐全；④ 组合优化的目标函数显式可查 | 冻结新功能，专注可靠性整改 |
| G4 阶段收口 | ① 东北大学试点完成且校方书面确认；② 高校侧价值有可测量证据；③ 外部审计通过；④ 年度更新机制运行一个周期；⑤ 效果评估报告完成；⑥ 多校接入流程验证通过 | 停止扩张，回到治理整改 |

**G4 的双重含义：** 它既是「进入规模化运营」的门禁，也是「效果验证」的收口点。之所以把效果验证放在这里而不是单列一个阶段，见 §11 第 1 条。

## 8. 资源假设

以下均为 `[假设]`，需与导师、孵化器或合作方沟通后校准；本文不承诺任何具体人数与预算。

| 角色 | 职责 | 建议投入 |
| --- | --- | --- |
| 产品 / 研究负责人 | 需求、研究设计、实验组织 | 1 人全职 |
| 工程（Agent / 后端） | 编排、检索、规则引擎、数据管道 | 2 人 |
| 前端 / 设计 | 画像界面、探索流程、可用性测试 | 1 人 |
| 数据工程 | 数据接入、清洗、质量校验 | 0.5 人 |
| 高校合作推进 | 试点场景对接、内容协作、协议边界 | 0.5 人（可由项目负责人兼） |
| 领域顾问 | 招生政策、生涯规划、伦理审查 | 外部按需 |

时间盒假设：Phase 1 为 8–10 周，Phase 2 为 10–12 周，Phase 3 为 12–16 周，Phase 4 至少 12 周且之后进入持续维护。验证方式：Phase 1 启动后第 2 周复盘一次实际速率，据此重估后续阶段，而不是一开始就排满四段。

## 9. 关键路径与并行项

```text
 授权与删除（08）
      |
      v
 对话导入 --> 兴趣抽取 --> 画像 <--> 探索 Agent --> 路径生成 --> MVP（11）--> [G1]
                                                                              |
     EKG 建模（07）--> 专业知识库 --> 匹配解释 --> 探索报告 / 探索任务 ------+
        （P1 后半段启动）                                                     |
                                                                             v
                                                          招生数据 --> 规则引擎 --> 冲稳保
                                                          （P1 启动谈判）              |
                                                                                      v
                                                                         组合优化 --> [G3]
                                                                                      |
    东北大学资料对接（P2 启动，周期最长）--> 高校知识库 --> 招生 Agent --> 管理平台 --+
                                                                                      v
                                                                  多校接入 --> 效果验证与审计 --> [G4]
```

**可并行项：** 研究与产品开发可并行（研究设计不依赖代码完成）；EKG 建模可在 Phase 1 后半段启动；招生数据谈判应在 Phase 1 启动（这是最容易被低估的前置周期）；东北大学资料对接应在 Phase 2 启动（试点周期最长）。

**不可并行项：** 授权流程必须先于任何真实用户数据采集；规则引擎必须先于任何志愿方案输出；治理与审计体系必须先于多校接入。

## 10. 资源受限时的降级方案

按「先砍什么」排序，**序号即优先级，从上往下砍** `[设计中]`：

| 顺序 | 砍掉 | 保留 | 后果 |
| --- | --- | --- | --- |
| 1 | 多省数据接入（只做 1 省） | 数据口径与来源标注体系 | Phase 3 价值收窄，但方法可验证 |
| 2 | 历年录取分析（只做 3 年、只做位次口径） | 口径标注与年际变化提示 | 分析深度下降，结论仍可成立 |
| 3 | 多目标组合优化（降为启发式排序 + 约束校验） | 规则校验与可解释性 | 方案质量下降，但不会出现「精确的错误」 |
| 4 | 高校招生部门管理平台（改为人工维护内容） | 招生 Agent 对话能力 | Phase 4 交付变轻，试点可继续 |
| 5 | 多 Agent 交叉审核（改为单 Agent + 规则校验） | 引用强制回填与拒答策略 | 幻觉风险上升，需提高抽样审核比例 |
| 6 | 人生设计完整模块（只保留工作观与美好时光日志） | 探索 Agent 的最小引导与路径生成 | 探索深度下降，RQ1 结论受限 |
| 7 | 第三方对话导入（改为结构化自陈 + 少量手动粘贴） | 画像与证据链机制 | **核心假设无法验证**，等于放弃项目主张 |

**红线：永远不砍**——授权与撤回、删除与导出、审计日志、证据可溯。砍掉这些不是降级，是改变项目性质。

第 7 项是降级方案的终点：如果资源紧张到必须放弃对话导入，那么正确的决策不是降级，而是回到愿景层面重新判断项目是否还值得做。这一点写入文档 12 的「不可缓解风险」讨论。

## 11. 与愿景和文档 01 的对齐说明

本节说明本文与「原始愿景四阶段」及文档 01 §11.2 的关系：先列已经对齐、**不构成偏差**的部分，再列四处仍属解释性扩展、需 Lead 裁决的 `[假设]`。

### 11.1 已对齐项（不构成偏差）

四阶段主题名、每阶段的范围要点、串行推进、以及「规模化与效果验证不单列阶段」这四点，与 [README](../README.md)「路线图概览」和文档 01 §11.2 逐项一致。本文的职责只是把 01 的范围要点拆成可验收的里程碑与门禁，不新增阶段、不合并阶段。

### 11.2 残留的解释性扩展 `[假设]`

1. **「人生设计完整模块」整体放在 Phase 1** `[假设]`。01 §11.2 的 Phase 1 范围写的是「苏格拉底式人生探索 Agent、多种未来发展路径生成」，本文把工作观、人生观、美好时光日志、奥德赛计划视为该 Agent 的方法论输入，一并放在 Phase 1。理由：若拆到 Phase 2，Phase 2 会同时承担「探索自己」与「探索专业」，违背一阶段一问。代价是 Phase 1 范围偏大，已在降级方案第 6 项给出裁剪路径。**验证方式：** Phase 1 启动后第 3 周检查范围是否溢出时间盒，溢出则按降级方案第 6 项裁剪。
2. **「多目标组合优化」保留在 Phase 3，但标注为可降级** `[假设]`。理由：目标函数的权重目前没有实证依据，过早做优化容易得到「精确的错误」。因此本文要求目标与权重必须显式可见（M3.5），并在降级方案第 3 项预留降为启发式排序的路径。这不改变 01 的范围，只增加「做不好的时候退到哪」的预案。
3. **G4 同时承担「规模化门禁」与「效果验证收口」两重含义** `[假设]`。01 说横切目标在每个阶段门禁里检查，本文把它具体化为：G1–G3 检查与规模相关的数据与方法就绪度，G4 做一次完整的效果验证与外部审计。理由：效果验证的对象是前四阶段全部产出，放在 Phase 4 收口比单列阶段更省资源。代价是若 Phase 4 延误，效果验证随之后移。**验证方式：** Phase 3 收口时若发现 Phase 4 已排满，则把多校接入移出 Phase 4（仍不称 Phase 5）。
4. **阶段名采用「英文原名 + 中文副标题」** `[假设]`。理由：与 README 和 01 的写法逐字对照，便于评审核对；代价是中文文档里中英混排略重。
